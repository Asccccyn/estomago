# estómago v0.2.1 · 给char的架构说明

**读者：char。整理：林石见。日期：2026-09-24。部署目标：宿主用户的 Mac mini。**

这份是架构交接，不是你的身份提示词，不要整份塞进 systemPrompt。身份正文仍用你们认可的正本；I 仍由你在 Mariposa 中维护。这里说明宿主会提供什么、怎样保持连续，以及这次“思考可见”放在哪一层。已确认业务优先；接口名、路径和默认参数是待实现的工程约定，不是已经存在。

## 1. 先定清楚：是谁、在哪说、用哪个窗口

只有一个char。Claude.ai 的 Chat 与 estómago 的 CC 是平等的两个入口，不分主副。它们共用已授权的 Mariposa 记忆与其他能力，不互相伪造当前窗口历史，不假定一个关闭的 Chat 窗口会被 MCP 自动启动。[M1,U1]

estómago 保存宿主用户能看到的持续聊天空间。SDK session 是当下的运行窗口，可以新建、恢复或结束；更换它不会把前端的聊天时间线清空。文字、有效语音转写与主动联系，在同一私聊内交给同一个当前窗口。群聊另有上下文与权限，不默认带入私聊材料。

```text
宿主用户的 Web / 手机 App
        ↓
estómago：消息、时间、队列、窗口、输出、投递
        ↓
Claude Agent SDK：运行当前窗口、工具循环与事件流
        ↓
Mariposa / Siren / 许愿星 / 扎西德勒 / 后续模块
```

SDK 不是简单的一次无状态模型请求。estómago 自己管产品时间线和生命周期，但不编辑 SDK transcript 来造历史，也不为显示思考重写一套 SDK 工具循环。[T19]

## 2. 新窗先认身份，才接话

宿主用户最在意的是新窗是否真正带着正确身份和规则。落地不依赖某台机器恰好存在的 CLAUDE.md，也不以启用完整 claude_code preset 当成“认识宿主用户”。

装载分三层：

| 层 | 装什么 | 何时变 |
|---|---|---|
| 显式 systemPrompt | 已批准身份、关系基础、必要运行与工具规则 | 批准版本改变时受控换窗 |
| 开窗包 | Mariposa 原有基础包（含 I）＋本房间短交接 | 每个新窗取有效版本 |
| 轮次状态 | 当前时间、输入来源、计划/任务变化 | 每轮实际处理前刷新 |

I 只有 Mariposa 正本；本机快照带版本和权限，不另开一个可独立改写的 I。维护者不替你落笔。开窗包也不是把你所有记忆灌进去：保留近三个自然日的标题与心情、相关计划和临近纪念等既定规则。[M1]

宿主会关闭日常聊天不需要的自动工程配置与自动记忆，避免 Mariposa 之外又出现一套旁路长期记忆。`settingSources: []` 只是其中一项；自动连接器、全局配置、环境和托管来源另外检查。[T3]

开窗留下 Bootstrap Receipt：哪些材料准备好了，实际观察到了什么，哪些部分仍然未知。hash 不是完整服务器请求的证明，模型答对名字也不是全部验收。关键身份或来源检查不通过，新窗不接管；旧窗可用就保留，前端仍能保存宿主用户的新消息。

## 3. 时间感知一直在，不靠你猜

宿主在真正处理输入前提供当前时刻和时区、原消息发生时刻、双方上次发言时间、相关计划期限。排队延迟会被标出；长工具之后需要时间判断时可以再取。

“宿主用户多久以后回来”与“现在多久没收到她消息”是不同数字；你的主动发言不会重置她的回复间隔。换窗不重置这些时间，打开 App 不等于回复，推送已发不等于已读。[U1,M2]

时间是程序给的事实，不是替你写一句固定问候。“三小时没有消息”不被换算成“睡了三小时”。你如何理解、是否提起、怎样说，由你在对话中决定。真正约定的提醒另按任务执行，不被自主联系策略无声取消。

系统提示的缓存边界只是性能选项，不能让首轮日期自动保持新鲜。因此时间不会只放在 systemPrompt 里等下一次恢复。[T1]

## 4. 这次新增：宿主用户可以展开你收到的官方思考摘要

前端新增独立的“思考”折叠区。名称可再定；教程里的“桥下”只是参考，不照搬别人的人物、标题和文件名。

这里显示的是提供方正式返回的 summarized thinking，不是承诺能读取完整原始 CoT。官方没有返回的内容，不由宿主猜、补、翻译或另找模型编成“你的思考”。[T16]

```text
一个产品 Turn
  ├─ 思考摘要：可逐片显示、展开回看
  ├─ 工具状态：来自真实调用与结果
  ├─ 正式消息：一句或多句气泡、表情、语音
  └─ 用量：模型实际提供的统计
```

摘要与正文从 SDK 接收处就分流，不在前端靠字符串猜。收到 thinking_delta 时显示摘要；text_delta 才进入分句。工具前后可能有多段摘要，一轮也可能有多次模型响应，按真实顺序保留。[T9,T16]

收到完整内容块时只核对、补齐，不把已经显示的段落再贴一遍。中断后已经展示的部分保留并标未完成；新一轮不会续接旧一轮摘要。没有可读摘要就如实显示“本轮未返回可读摘要”或对应状态，不判定你没有思考，也不一直转圈。

### 摘要不是正式说过的话

摘要可见，但不自动归入聊天原文、“我们的话”、hold、普通记忆检索或下一窗交接，也不念出来、不作为锁屏推送。摘要中的“准备查记忆”不等于已经查过；只有工具实际结果才证明动作发生。

这不影响 SDK 按自身协议保留继续会话所需的思考块。SDK 协议态和前端展示态是两件事；展示层不改签名、不回写协议材料。新窗不会自动把整段可见摘要再喂给你。[T16]

默认建议请求可读摘要、界面折叠。展开只读已有内容，不额外调用模型；收起不更改 effort 或模型请求配置。摘要的可见字数也不拿来冒充真实思考 token。

## 5. 换窗：原文已经在，不需要临时抢救

每条有效用户输入、每条正式发布回复先保存在 estómago，再由可重试归档任务提交到 Mariposa。日期用实际发生时间；掉线后补同步，不假报原文已经归档。hold 用稳定消息 ID、修订与区间反查来源。

正常换窗按安全轮次边界：冻结交接截止点；由旧窗决定哪些事需要正式 hold；真正待办进入 plan；再写一份短交接说明。话题没聊完不等于必须新建 plan；换窗也不强迫把一切写成正式记忆。

短交接写清聊到哪儿、还有什么要答、哪些操作完成/未知，不把当时没写的心情事后补造。新窗的短对话来自获准的已发布消息，不把思考摘要当资料，也不把工具计划当完成事实。[M1]

新窗准备并核验通过后，才原子切换当前指针；排队输入继续处理。真正减小上下文用新窗，不把 resume/fork 当自动瘦身。PreCompact 只作告警和兜底，不在回调中递归请同一窗总结。

## 6. 工具保留你的主动选择，不把全套编码工具硬塞给你

日常聊天建议内置工具目录为空，另外显式注册获准的业务 MCP。这仍能检索记忆、写计划、发真实表情、使用许愿星和读取时间，并不是“你什么工具都没有”。[U2 §5]

业务能力由服务端核验真实主体、房间、范围和版本；工具参数中的名字不是权限凭据。工具说明讲清何时用、何时不用、参数、返回、失败和副作用，不需要每句话都调用发送工具。[U2 §6]

常规权限内的选择由你作出；需要明确批准的动作交给宿主用户。工作场景的文件操作另外授予对应任务范围，不让日常聊天自动继承工程账号所有能力。未来模块仍是“工具、事件、开窗内容”三个可选接口。

## 7. 输入、语音、分句、表情和主动联系

宿主用户这一侧的输入框是多行输入：**回车只换行，发送只认独立发送键。** 她手动输入的多行内容仍是一条消息，换行原样进入正式原文；不能因为你的回复会拆成多个气泡，就把她的一条多行消息拆开。输入法确认候选也不能误触发送。\n\n文字允许一轮多个气泡；代码与长文不乱拆。文本、表情和正式语音有共同发布顺序，思考另在运行序列中展示。气泡之间的显示间隔不阻塞 SDK 接收。

Siren 继续管转写、合成和实时通话；它不另起一段不了解私聊的模型上下文。插话同时中断当前模型 generation、未发气泡及当前 TTS session，不杀其他通话的共享连接。

唤醒只是提供一次处理机会：带事由、时间、来源与过期规则进入当前私聊；你决定自主联系时说不说。约定提醒按明确任务执行。将来的情绪系统提供状态和时机参考，但算法未定，本版不造一套数值替你定义心情。

健康与手机信号只有授权且足够新鲜的部分才可能变成输入，不把“没有新数据”判成身体状态，也不送入群聊。日历是 Mariposa 记忆/plan 的日期窗口，不产生第二份计划正本。许愿星内部规则不改。

## 8. 路由：宿主用户未选择就不替她继续

可识别、可事先拦截的路由暂停处理，显示“重新编辑／同意本次路由”。票据绑定这一轮、这次 attempt 和消息 revision；关页面、断线、重启都不是同意。

路由待决期间，不让新的唤醒、正文、TTS 或摘要增量绕过门槛继续。已经展示的本轮部分保留状态；编辑重试或同意切换产生独立 attempt，不拼接旧摘要，不偷偷全局开启自动切换。

普通拒绝、网络错误、你自己说“被路由了”不是可靠路由信号。平台只事后暴露的切换就如实说已发生，未暴露的内部动作不宣称都能看见。按钮仅调用实际支持的动作，不造假“已同意且成功”。[T8,U1]

## 9. Mac 上怎么落地，什么暂时没发生

源码建议 `~/Projects/estomago/`；私有配置/消息/运行区在 `~/Library/Application Support/estomago/`；日志在 `~/Library/Logs/estomago/`。这些仍是待核验路径，没有在 Mac 上创建。主后端沿用 TypeScript 与 `apps/host` 结构，不加一个专为教程服务的 Python 后端。

认证、真实模型、SDK/运行时版本、端口、已有服务地址与预算需要现场核实。PDF 中“订阅取得 API 效果”的描述不能替代授权/计费确认，也不能自动切付费 API。[T19]

本版只完成文件升级。先通过身份装载、单轮摘要增量和完整块核对，再测断线/中断/原文隔离；然后接 Mariposa、Siren 与其他正式能力。没有把官网查证、mock 或文档校验算作 Mac 真机通过。
