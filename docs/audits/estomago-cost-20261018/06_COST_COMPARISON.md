## 2. 为什么 $0.0422/$0.0524 是"合法下限附近"而非异常

交接样本拆账（林石见核算 + Codex 逐笔对账，两路独立一致）：

| 来源 | Token | 单价($/M) | 费用 |
|---|---:|---:|---:|
| 缓存读取 | 37,351 | 0.50 | $0.0186755 |
| 1h 缓存写入 | 1,153 | 10.00 | $0.0115300 |
| 普通输入 | 3 | 5.00 | $0.0000150 |
| 输出 | 480 | 25.00 | $0.0120000 |
| **合计** | | | **$0.0422205** |

结构性下限：同一请求即使**全部输入按缓存读价**计（写入归零），加 480 输出仍需 $0.0313；95k 上下文常态后单次缓存读取本身 ≈$0.0475。**在保留现有上下文、模型、1h 缓存与工具续轮的前提下，$0.02/消息不可达**——本批按任务书不将其设为验收指标，也拒绝用删功能的方式"达标"。

写入侧的经济性（任务书 4.2 的核心问题）：每轮 ~$0.004-0.012 的 1h 写入换来下一轮同段按 $0.5/M 而非 $5/M 读取（10 倍差价），112 笔数据证明写入全额复用——**滚动缓存（方案 A）就是多轮最优，保留**。

## 3. 四类结论（严格区分）

**A. 已确认并修复的真实成本问题**
- A-1 引用误拒后的重复回读链（三条 $1.714 已知费用的直接根因）——`6e48036` 修复（本批之前），修复后未再发生；节省金额未做付费对照（归 D 复验）。
- （本批自身无 A 类——未发现新的可修费用缺陷。）

**B. 已确认正常、不是 Bug 的费用**
- B-1 $0.0422/$0.0524 稳态单消息费用：缓存读+增量写+正常输出的合法组合，见 §2。
- B-2 $0.953375 整段重建：许愿星 13 项工具上线（c85c964）+重启的一次性部署成本，后续两笔恢复满复用。
- B-3 17:20 的 94,961 写入（memory_recall 日期参数）：真实 schema 变更，同上一次性。

**C. 可继续优化但涉及产品行为变化、需她裁定的事项（本批不动）**
- C-1 95k+ 上下文的常态读费（~$0.05/消息）是"保留完整轨迹+工具面"的价格。若想显著降本，可选项只有产品级（例：换窗软线下调=更短轨迹、或低频场景用更便宜档位）——均违背本批约束，仅记录供未来裁定。
- C-2 工具冻结快照进程内存储：改词表+重启会并入一次整段重建（02 §4）。持久化快照可消除，但引入跨进程状态，收益仅省罕见一次性 $0.5-1，不建议。

**D. 已修复但尚未经真实账单验证的事项**
- D-1 `6e48036` 的实际节省金额（三条链 $1.714 中"正常 hold 也需要模型调用"，可省部分 < $1.714，未实测）。
- D-2 本批 v28 指纹列：生产部署后下一批真实派发自然验证（无需付费测试）。
