# 分批执行、优先脱离工作树与发布验证

每批按“读当前代码与真实消费者 → 确认唯一责任模块 → 重构并接真实入口 → 同步退役旧路径 → 验证 → 提交回执”执行。不是先写平行新功能，再把清理和拆分留给最后。

v1.1 的聊天形态是前端单窗口、后端顺序滚动模型上下文段。滚窗到达既有容量条件时，携带选定原文和开窗包；只在这条已有链路增加图片/留言贡献，不改变阈值、不新增会话分支、窗口领取器或多窗口 UI。下文“部署窗口/迁移窗口”是运维时间段，与聊天滚窗无关。

代码依赖顺序：P0 → P1 → P2 的实现与预演；P3/P4/P5 在共享合同稳定后可按独立模块并行。P2 的生产迁移闭环必须在正式 release 实际接管消费者的发布窗口内完成，见 P6；生产暂停时记录“代码/预演完成、生产迁移未执行”，不冒充完成，也不阻止无依赖的后续代码施工。并行任务不能同时改一份合同或用彼此未提交的接口猜测施工。

## P0：最优先——固定当前基线，向量服务离开工作树

### 0.1 有限基线核对

记录最新 diff 审计/修复报告对应的 E、M 提交、当前 HEAD、未提交变更以及各生产服务实际运行的 release。仅检查与本次实施有关的版本、入口和合同，不重跑已经完成的 diff 审计。旧附件记录的提交不得作为强制基线。

阅读当前 AGENTS、服务运行/发布说明和现有契约。遇到他人 WIP，记录并隔离自身改动，不 reset、stash 覆盖或顺便清空。

### 0.2 查清 media-embedding 真正从哪里运行

核实实际 launchagent/进程管理条目（旧简报给出的 label 只是定位线索）、启动脚本、进程 PID/argv、工作目录、监听地址、健康响应、E 的调用配置。不要输出完整环境变量、bearer 或密钥目录内容。

同时检查以下隐含开发依赖：

- ProgramArguments、WorkingDirectory、包装脚本、环境里的 PYTHONPATH。
- 可执行 Python/虚拟环境、editable install、.pth、符号链接真实目标。
- 实际导入业务模块的来源文件、运行时 sys.path，以及是否还解析到日常开发工作树。
- 文件监听、自动 reload、开发启动方式、重复守护进程。
- 模型 cache、向量索引、待索引进度及其他可变数据的位置。

“主脚本放进 release，但 import/虚拟环境/软链接仍指回工作树”不算完成。

### 0.3 构建固定且可追溯的正式 release

复用当前项目的 release 目录与发布约定，内容来自已核对的提交/构建产物；记录提交、构建指纹和依赖锁定情况。不要把一个仍会被日常施工修改的 checkout 改名为 release 充数。

业务代码与依赖运行时不得依赖开发目录。权重继续使用已存在的本地固定 revision cache，不因为迁移目录重新下载一份，也不更新模型版本、量化、向量维数、预处理、归一化或并发参数。运行时数据留在明确的可变数据目录，不能随 release 清理一起删除。

核实目前实际生效的 model/revision/embedding 指纹；只记录必要标识。不把旧简报的值伪装成现场读取结果。若实际版本与已修复基线冲突，报告差异并暂停相关切换，不趁机进行模型升级。

### 0.4 真正切换现有服务

在切换前准备同样不依赖工作树的回滚 release。沿既有服务管理机制执行有界的停止/启动或正式切换；排空现有索引工作或保存其可靠进度，避免两个实例同时写同一索引。只处理本服务，不重启不相关的通话和聊天服务。

用户本轮已授权这一项优先直接接入，不因旧附件中的“重启需单独同意”重复等待。若执行环境存在真实访问限制、版本不明或无法安全保留索引，则按阻断模板报告具体原因，不能假称已切换。

### 0.5 必须通过的验证

1. 新进程实际运行 release 路径，旧实例退出，端口与调用方一致。
2. 健康响应可用；本地模型固定身份、维数/预处理与迁移前合同一致。
3. 一个已知文本查询与一个已知可读取图片样本经现有调用链可用；不调用远端收费模型。
4. E 的既有媒体查询及增量索引入口仍能到达新进程，既有向量和进度没有清空或重复创建。
5. 应用源码/依赖的真实解析路径不含开发工作树；运行报告能说明 release 归属。不要修改用户开发文件来做这个验证。
6. 停启后的服务与启动项只存在一套有效配置；旧开发启动脚本/启动项没有仍在生产使用的路径。保留必要开发便利脚本时明确只用于开发，不能成为生产启动 fallback。

P0 未成功不得把 M 媒体迁移叠加到不稳定的检索运行环境上。可继续无依赖的需求实现，但不能宣布进入生产接线完成状态。

## P1：媒体共同合同与唯一职责

按 02 盘点真正存在的资产引用、M 上传能力、content 引用账本/操作协调器、E 图片物化和索引消费者。不要根据旧报告字段名直接开新表。

产出最小合同映射：逻辑操作 → 现有实现 → 唯一责任模块 → 需要修改处 → 被替换旧路径。优先扩展现有能力；只有确有缺口才加明确的新操作，且不能与已有操作重叠。

锁定 M 资源身份、真实文件读取、内容版本、相册关联、存档来源范围、搜索 scope、状态回执与 E 的统一带入图上限合同。一个规则只有一个正本；各调用方的校验通过共享合同或正式能力取得。

M 为原件和资源生命周期负责；content 为业务分类/留言负责。展示标记可使用可重建且允许短暂延迟的最小投影；防止原件回收的 content 引用保护必须沿既有 pin/commit 或等效的已确认保留合同。引用状态未确认、投影尚未补齐或权威关系暂不可核对时，不得据此判定无引用并回收。两者均不能变成第二套可编辑相册主表。查询过程中不能出现 E→M→content→M 的循环回源。

### P1 退出条件

边界明确；读取方列表完整；关键模型可见工具复用既有 registry/权限/延迟加载机制；没有第二套上传、开窗、媒体索引调度器或通知总线。共享合同已经被真实入口引用，不能只写一个无人使用的 types 文件。

## P2：新媒体进 M，历史媒体迁移与旧正本退役

先实现新文件经现有 prepare/stage/finalize 保存于 M，成功后挂接聊天或内容条目。E 可以有限暂存传输失败的唯一输入，但必须有可见状态和后续处理，不得清理未成功迁移的唯一字节，也不把暂存变成永久影子库。

图片生成已成功而保存未成功时，复用那份实际结果重试保存；不能再次执行付费生成。对外只有持久化完成才返回已保存成功。

历史迁移必须有可恢复进度和 dry-run 清单：旧资产 → M 稳定引用 → 校验结果 → 读取消费者切换结果 → 旧文件可清理状态。按相同字节 hash/长度验证，不将重编码后的缩略图当作原件。中断重跑幂等。

所有消费者一起切：聊天附件、M 原文页、E 相册/作品、媒体读取工具、模型请求图块物化、索引读图、历史引用、导出/预览及已有下载入口。复用既有鉴权，不能因为 hash 可猜就改成公开桶。

已经出现在历史消息中的旧 asset ID 可以保留为到 M 对象的持久数据别名，通过唯一解析器回到 M；这不是保留 E 文件回退。不能为了删除一张映射表改写已冻结的聊天历史或损坏旧链接。迁移适配退出时，删除的是双读/双写分支，不是仍必要的稳定历史身份。

代码中已替换的 E 旧生产落盘写入和旧回源读取分支、过时配置/注册/测试，在本批改动里同步退役。物理旧原件只能在新正式 release 已实际接管全部生产消费者、迁移校验与最终增量收尾成功后删除；不能凭新代码的本地测试通过，就删除旧生产 release 仍在读取的文件。

若整体发布安排在 P6，P2 先交付实现、隔离环境验证、迁移 dry-run 和可执行切换/清理步骤；实际迁移、正式读取切换和物理清理在 P6 的同一次迁移窗口闭环，不是把死代码审计推迟到结尾。生产发布被明确暂停时不要提前清理原件，真实状态写成“迁移未执行”。窗口内沿既有维护或增量对账机制处理扫描后新增的媒体，不能漏掉仍写入旧库的最后一批文件。迁移记录和必要历史 schema 按项目规定保留，短时双份不得变成日常长期备份。

### P2 退出条件

分别记录两项状态：实现/预演通过，以及生产迁移闭环完成。前者用隔离数据贯通 M 原文、E 聊天、作品/相册和模型输入；后者还必须核对正式对象/引用数量和迁移异常，证明全部真实生产消费者不再依赖 E 旧字节，且清理发生于目标校验和正式切换之后。失败条目未被当成功、未失去唯一原件。未发布时只能报告前者，不宣称整个 P2 已完成。

## P3：四类入口、制作与精选

按 04 复用现有 content/creations/albums 完成 E 人类 UI、模型工具、真实作品版本与资源、图片生成适配、表情包归类、精选留言及携带设置。

不要把“有后端接口”当 UI 完成，也不要让模型读到列表却无法打开实际资源。不存在图片生成 Key 时，将真实远端生成用例标为阻断；适配、真实保存链与本地固定输入验证仍继续。不虚构一张生成图作为上线证据。

携带设置入口立刻执行统一的 10 张有效选择规则；沿用已有写入校验和重复操作身份，不因本功能新建跨客户端协调。第 11 张被拒时其原有收藏和留言不得丢失，仅携带变更不提交。同一选择的重复提交不能多添一张。

作品从 M 打开时，源文件与版本完整。需要编辑时读取 M 对应版本；不在 E 数据库另存永久完整源代码。执行内容用既有隔离查看方式，不继承聊天业务凭据。

### P3 退出条件

四入口能实际操作；“收藏/制作成功”都有真实可打开对象；同一文件多分类不多存；Key 未配置等真实限制清楚；被替换的旧制作保存和 E 文件读取路径已经退出。

## P4：对话存档、双方通知与争吵停止

按 03 接现有选区/存档前端，固定已发布消息范围和版本。支持模型可靠定位、不额外回读全文。无法精确定位任意长片段时明确支持边界并报告，不能猜范围。

复用现有事务/操作协调/恢复机制建立存档及最小投影。原文保存不依赖存档成功，原文不能因移除存档被删除。存档后 M 的来源标记与记忆绑定分别显示。

通知与取消沿现有事件、工具回执、回复取消和播放取消链实现。不要让一个 UI 收藏动作创造新的后台对话回合；一次提交派生一次通知。对用户结束争吵，即使持久化随后失败，当前停止输出的意图也应保留，不能因为存档失败而自动恢复争吵输出；前端分别显示“已停止”和“存档未完成”，不能冒充存档成功。封存立即生效以 content 权威范围为准，E 在既有最终投递资格处复检，不能等待 M 投影，也必须覆盖封存前已开始的在途候选，详见 03 第 6 节。

### P4 退出条件

争吵/甜蜜均可真实保存与打开，来源范围正确；当前上下文段不因存档改写；通知无重入；取消目标正确且不影响下一条新回复；自动浮现与默认滚窗携带入口尊重封存范围，主动查询仍能看。存档不触发额外滚窗，正常容量滚窗继续按原流程。所有测试必须以已发布真实消息流程构造，不再出现“草稿一边应可读一边应拒绝”的冲突语义。

## P5：检索与既有滚窗真实携图

按 04 接 Gemma 媒体查询、M 文本存档检索；索引只随资源/模型指纹真实变化重算，不因存放目录变化全量重建。增量索引复用现有消费者，区分服务忙、未索引、对象不可读和正常无匹配。

按 03 在现有滚窗装配中合并每次滚窗、下次滚窗一次与所携带原文中的图片，明确最终清单、去重并执行总数 10 与实际图片块 10 的上限。以 E 既有上下文预算为准，图片与留言都参与真实预算；不要把记忆浮现预算误用成整个开窗包额度。必须验证原有选定原文和开窗包继续进入下一段，不能只验证新增的照片。

超限在可审查清单上显示来源并要求减选，不自动删除原文中的图片、不暗中挤掉每次滚窗图片、不塞前 10 后假装全带。“下次滚窗一次”在下一次既有滚窗成功且图像与留言确认投递后消费；同一次滚窗的恢复/重试复用原操作，不额外复制携带内容。确认未成功投递则保留待带入，未知状态沿原运行记录核对，投递后再停止回复或播放不撤销消费。删除 v1.0 错加的并发新窗领取、跨窗口目标绑定要求。

当前上下文段内冻结图片输入与留言；下一次滚窗在现有开窗包流程中采用新的有效选择。前端始终保持原来的连续聊天时间线，不因为后端换上下文而分成新聊天页或重复显示一遍携带原文。照片保留来源身份，不伪装新用户发言。所有视觉路由通过既有发送适配验证，不能把 tool JSON 里的引用当成图像已经送达。

### P5 退出条件

已验证既有容量滚窗、前端时间线连续、原文和开窗包保留，以及 0/9/10/11、跨模式组合、重复选择、去重、预算不足、视觉不支持、资源失败、同次滚窗取消/重试。网页刷新/重连不触发滚窗或消费一次设置；不验证也不实现并发开窗。10 张只是数量上限，不构成费用或上下文总量保证。检索负例真实返回无匹配，未通过真实联调的项目标明阻断。

## P6：最终功能验收、迁移切换与回执

只执行 06 中与最终提交相关且尚未验证的功能/集成检查；已验证且无相关变化的用例不重复扩大。核对每批退役清单和依赖边界证据仍对应最终版本，不新开一轮泛化专项审计。

若 E/M 整体发布已在当前执行会话授权，沿既有 release 流程部署本批受影响服务，在同一窗口完成 P2 的真实迁移、正式消费者切换、最终增量核对、旧原件清理和真实冒烟；若仍有明确有效的整体暂停，准备构建与迁移件、说明具体依据，不能把这种状态写成已上线或迁移完成。P0 的向量服务优先切换独立于相册整体发布，不拖至 P6。

回滚应切到兼容 M 唯一资源正本的 release/前向修复路径，不允许简单恢复旧 E 本地媒体写入器。迁移前先准备兼容回滚或完成桥接验证；无法保证无丢失恢复时暂停破坏性清理并报告。

保护对象存储、模型权重 cache、向量索引和业务数据目录，不把它们打包在可随意删除的 release 内。必要迁移快照属于有期限、可解释的恢复措施，不得衍生一套 E 永久媒体备份；生产备份策略本身沿原有 M 备份机制执行。

最终交付 07 回执、提交列表、功能证据、迁移结果、受影响旧路径退役结果、全部剩余阻断。省略、延期或改方案必须保留对应用户决定，没有决定就仍是待办而不是完成。
