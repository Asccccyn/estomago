# GLM 执行总指令：相册、作品、对话存档与 M 媒体唯一正本

版本：1.1（滚窗语义修正版）；修订日期：2026-11-08。用户：宿主用户；对话模型称呼：char；方案整理：林石见。

## 本版先纠正一项错误假设

前端始终是同一个连续聊天窗口。后端在现有上下文容量条件下，携带选中的真实原文和开窗包，顺序滚入下一段模型上下文；这是用户现有的“滚窗”，不是让用户创建多个聊天窗口或并行会话。

本包所称“下一窗”只指下一段模型上下文；“开窗包”沿用现有名称。照片只接入既有滚窗装配和投递流程，不修改滚窗触发阈值、原文选择规则或前端会话形态。已有手动滚窗入口如存在则沿用，不另建多窗口功能。

v1.0 中“两个新窗并发领取下窗一次”“派发前绑定唯一目标新窗”“跨客户端开窗争抢”是林石见误加的设计，全部撤销，不得实施。若已经据此施工，只撤销这些错误引入的新增功能，保留原有串行滚窗、必要的同次重试防重和其他已完成相册工作，不做整仓回滚。

## 先执行什么

从最新“diff 审计已经完成、问题已经修复”的实际提交继续施工。不要重新安排一次全量审计、死代码专项审计或深耦合拆分专项。先记录当前已修复基线，然后优先完成 media-embedding 脱离工作树、进入固定 release 并真实接回现有服务。之后按 05 的批次完成全部相册功能。

这是一份实施指令，不是调研建议。用户已对齐产品行为；你应读实际代码、复用已存在能力，完成重构、接线、数据迁移、前端交互与有意义的验收。不得只写方案或占位接口后交差。

## 两条必须在施工开始做到的工程要求

### 1. 替换功能的同时退役旧实现

每批建立被替换路径清单，沿真实入口核实消费者，更新引用后在同批删除不再使用的业务分支、旧上传/读取路径、空工具、旧配置、过渡测试和过期说明。不能新旧两条生产路径并行，不能用永久 feature flag 藏起旧架构，不能说“最后再来一遍死代码审计”。

必要的迁移映射不是第二套业务：它必须只服务存量数据、有明确完成条件，退出时删除运行适配，仅保留必要的迁移历史与数据兼容合同。数据库迁移历史不能为了“零死代码”胡乱删除；仍被真实历史引用使用的 ID 也不能盲删。

### 2. 按唯一责任模块实施，不把重构债留给下一轮

M 管媒体字节、完整原文、原文附件关系和已有检索基础设施；现有 content 管作品/相册/存档条目、留言、分类与携带设置；E host 管鉴权、工具入口、聊天/上下文编排和模型发送适配；现有 media-embedding 服务负责媒体 embedding。通过明确合同协作。

禁止跨仓直接读写对方数据库、把对方源码作为业务依赖、在 E host 再写一套相册逻辑、在 M 再写一套可编辑相册正本、再启动一份千问、再造第二套开窗/召回/通知/后台恢复架构。可以复用通用机制，不能不加判断地把某个旧业务的全部状态机套到新业务。

每批完成即提交边界与退役证据。没有做到，当前批不能算完成；不把问题转交给未来专项拆分。

## 必须贯彻的产品行为

- 全部聊天图片、作品原件、表情包、需要保存的派生媒体都在 M；E 不长期落第二份媒体原件。
- E 的四个入口：作品、我们的相册、对话存档/截图相册、表情包。复用现有 content 与前端风格，不另建一套内容平台。
- 作品包含 SVG/互动小组件和生成图片；原件可真实引用、打开，不能以缩略图或临时外链代替。
- 我们的相册是明确精选；留言原样保留。携带设置为仅收藏、下次滚窗一次、每次滚窗。
- 每次滚入下一段上下文时，带入图片合计上限 10。合并跨相册、每次滚窗、下次滚窗一次与所携带原文中的图片；去重且实际图片块不得超过 10。配置入口和既有滚窗最终装配均校验，不能静默裁前 10、不能每个入口各给 10、不能自动扩大上限。
- 10 张不限制相册库存，不限制滚窗完成后的普通聊天继续发图。其他上下文预算仍照常校验，10 张不等于无条件放行。
- 争吵存档与甜蜜存档自动记录各自类型。存档不删除/改写当前上下文段的历史、不触发额外滚窗或清洗；正常容量滚窗继续沿既有机制。M 原文全量保留，前端聊天时间线保持连续。
- char通过明确定位存档；不能为存档再把片段全文读回模型，不得猜测任意争吵起点。无法保证的能力按阻断规则报告。
- 存档关系和记忆来源绑定分开；存档不自动建记忆桶、不改变既有普通召回/找话/原文二轮顺序。
- 存档成功后双方得到一次正确通知；用户点击结束争吵时，沿用现有取消链停止仍在输出/播放的那次回复。
- 表情包/图片复用 Gemma；存档文字复用 M 现有 Qwen 与 BM25。返回真实资源；无匹配、检索故障、尚未索引分别表达。

## 做不到或想简化时怎样处理

只暂停受到影响的功能及其依赖批次；安全且无依赖的工作可以继续。用 07 的阻断格式立即报告：对应需求 ID、源码证据、哪里冲突、已尝试什么、影响哪些行为、可选方案及代价。等待明确裁定后才能更改产品语义。

以下均不是可以自行更改需求的理由：实现费事、工期紧、没有现成 API、前端还没接、测试不方便、预计很少使用、觉得用户用不上。

任何功能建议省略、延期或降级，都必须单列并报告；未获同意不得省略。不要用“优化”名义把真实图改成链接、把组件改成快照、把真实存档改成模型总结、把模型存档改成全文回读、把找不到改成随便返回一张、把本地服务失败改成自动远端兜底。

常规实现细节可自主选择，例如适配实际函数名、复用已有客户端、按现有测试框架组织代码。不必为不改变锁定行为的命名或局部结构改进再次请求确认。禁止通过改合同、删测试断言或制造虚假成功规避阻断。
