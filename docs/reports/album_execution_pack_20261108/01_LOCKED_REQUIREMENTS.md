# 锁定需求与完成标准

本表是本包唯一需求总表。具体实现阅读 02—05；验收行号见 06。当前状态是“待 GLM 实施/验证”，不是完成声明。

v1.1 统一术语：用户前端只有一个连续聊天窗口；滚窗是后端把选定原文和开窗包带入下一段模型上下文。沿现有容量触发和已有手动入口执行，不新增并发窗口、会话选择器或跨窗口领取流程。“开窗包”保留既有名称；所有下次/每次携带策略均挂在既有滚窗链路。

## A. 本轮基线与施工纪律

| ID | 锁定要求 | 不允许的替代 |
|---|---|---|
| R01 | 从最新 diff 审计已完成且修复后的实际基线施工；记录 E、M、content/embedding 对应提交及脏工作树 | 再开一轮全量审计，或把旧简报 HEAD 当最新 |
| R02 | 每批替换时同步退役无消费者的旧实现、配置、工具和不再成立的测试 | 两条生产路径并存、永久过渡开关、最后再专项清理 |
| R03 | M/content/E host/embedding 各有唯一职责，通过现有模块和明确合同协作 | 跨库直写、源码耦合、复制一套业务、施工完再拆分 |
| R04 | 做不到即报告并暂停相关项；任何建议省略、延期、降级先报告 | 默默少做、伪造成功、放宽断言、写 TODO 后宣告完成 |
| R05 | 第一批真实完成 media-embedding 固定 release 化并接回现有入口 | 留在工作树、从 release 反向指回工作树、只写迁移建议 |

| R14 | 从相册移除只解除关系；仍被原文/作品/其他条目引用的对象保留 | 收藏移除导致历史图片消失 |
| R15 | 历史 E 文件校验迁入 M，所有读者切换后清理旧文件；保留失败项唯一副本 | 先删后验、迁移未完清临时文件、长期双写 |

## C. 精选照片与 10 张上限

| R18 | 每次滚入下一上下文段，跨入口合并后最多带入 10 张图片；唯一共享合同由 E 负责 | 每册/每模式各 10、后台绕过、可随意调大、静默截取 |
| R19 | 有效常驻与待一次带入集合在选择时防超限；既有滚窗装配再合并所携原文附件校验；重复提交不重复新增 | 前端能点到 11 后才暗丢；为相册新增跨客户端开窗协调系统 |
| R20 | 原件身份去重、实际发送图片块也不超过 10；同图多分类/历史与置顶重叠不重复注入 | 仅算条目数，条目里包几十张图，或重复图块绕过计数 |
| R21 | 上限仅约束滚窗带入，普通聊天后续发图和相册库存不受它限制；其他预算仍有效 | 10 张变成相册库存上限或普通聊天总图片上限 |
| R22 | 真图加原留言随选定原文与开窗包进入下一上下文段；段内冻结；前端仍是同一聊天时间线 | 只给 ID/描述说已看见；另建滚窗引擎或新聊天页面；每轮改旧 prefix |
| R23 | 下次滚窗一次仅在既有滚窗成功且图与留言确认投递后消费；投递前失败不消耗；同次恢复不重复带入；投递后停止回复不撤销消费 | 新增多窗口领取或目标分配；网页刷新即消费；未知状态盲重发或盲消费 |

## 不扩大范围

本次不重新设计记忆衰减、profile/I、Sol 语义判断、语音深听、通话生命周期、账户身份、原生 App 工程或页面美术系统。仅在已确定的入口上补相册所必需的适配。不得以“统一”名义改写那些业务；发现阻断性接口冲突按 R04 报告。

UI 应在已有 E 网页/响应式前端真实可用；可复用供原生调用的接口，但“未来会做 iOS”不能代替这次人类可操作界面。
