## 一、宿主用户怎么用

### 自动唤醒（三开关）
- **在哪开**：`PUT /api/v1/background/settings`（前端设置页待接——当前用 curl/工具调）
- **三个开关独立**：`autonomous`（自主活动）、`keepwarm`（缓存保温）、`reminders`（普通提醒）
- **怎么开**：必须先填 `daily_cost_cap_usd`（日费用上限，美元），否则 422"预算未配置"
- **注意**：即使开关开了，模型价格未配置（`or_model_price`）也会报 `BUDGET_ESTIMATE_UNAVAILABLE` 不花钱——这是保护
- **关掉会怎样**：不再开始新活动/保温，正在进行的后续步骤会停止；已产生的费用和已完成的动作保留

### 系统异常红点
- **在哪看**：前端顶栏"系统通知"按钮 + 徽标；或 `GET /api/v1/system-alerts/summary`
- **红点含义**：有未读的 warning/critical 系统异常（缓存异常/用量缺失/预算越界等）
- **已读≠恢复**：点过以后红点消，但待处理项还在，直到真实解决

### 单条消息 token
- **在哪看**：输入框下方常驻"本条文字约 N token"；点击展开看"本次请求输入约 T"
- **气泡上**：你的消息显示"发送时估计"；char的回复显示"正文约 N（粗估）"
- **整轮实际**：在记录面板看（每轮只出现一次，不摊进气泡）

### 日历
- **入口**：`GET /api/v1/calendar/month?month=YYYY-MM`（月概要）；`GET /api/v1/calendar/day?date=YYYY-MM-DD`（日详情）
- **各来源分别分页**：`GET /api/v1/calendar/day/items?date=...&source=chat`
- **外部源状态如实显示**：Mariposa/星星未配置时标 `not_configured`，不冒充有数据

### 朋友圈与内容
- **入口**：`/api/v1/content/*`（est 薄代理→独立内容进程）
- **双方都能看帖、发帖、评论**；letter 和 post 是同一数据模型只差展示
- **删除自己的帖子不会删对方的评论**（保留占位+评论）
- **三相册**：聊天截图（关联我们的话+反查）、重要照片（双方添加）、表情包（含义可搜索）
- **纪念作品**：只需图标就能创建（无作品=图标直达桶）；后补作品只是原记录加引用
- **未来留言**：正文归内容服务，投递时间归 est 调度器——结构性分责

### 聊天图片
- **发图**：📎 按钮→上传→发送（文字可空但有附件就能发）
- **模型真看图**：发图前自动查 OR 模型元数据确认支持图片输入；不支持就报 `MODEL_VISION_UNAVAILABLE` 阻断（不偷偷丢图继续答）
- **语音消息**：上传保存后，如果没转写就不唤起模型（`MEDIA_TRANSCRIPTION_FAILED`）；有转写会标注"来源：Siren"的派生文字

## 二、重要设计决策

| 决策 | 理由 |
|---|---|
| est 只做聊天宿主+薄代理 | 不把阅读/星星/社交浏览搬进聊天核心 |
| apps/content 独立进程 | 独立 SQLite/loopback/服务凭据；故障时聊天不受影响 |
| content 不反调 est | 避免同步等待链；资产校验在 est 侧完成后才转发 |
| 作者只从宿主派生 | 浏览器/模型都不能靠请求体自报作者 |
| 缓存计时=有读写证据请求的派发开始时间 | 200 无证据/字段缺失/失败均不虚刷 |
| 保温单请求+工具执行门拒 | 不为禁工具清空定义（破坏前缀）；执行时拒绝且无续答 |
| 模型终答不自动发布 | 自主活动唯一公开发言途径=chat_send_text 工具 |
| noop 是成功结果 | char醒来后可以选择什么都不做，不强制产出 |
| 价格门 | or_model_price 未配置=不开后台付费请求（预占须可信上界） |
