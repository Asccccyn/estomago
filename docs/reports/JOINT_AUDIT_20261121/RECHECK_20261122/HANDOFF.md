## 一次交给修复窗口的十项

### 01 · char正常说完的话，聊天、朋友圈和下轮上下文对不上【阻断，Host 回合发布】

**无须插话即可复现。** 在新窗发起心跳，先合法调用工具目录，再输出一条完整聊天正文并正常结束。API 和 SDK 的 direct/deferred 都把这句话带进下一次自然聊天，乔乔的聊天却少了它。换成先用 chat_send_text 正式发一条、再输出另一条完整正文，工具发送的那条保留，最后一条仍漏。另跑三个带正文的助手消息，前两条同时有工具调用、最后一条在揭牌后。两种适配器的规范轨迹都有三条，聊天和朋友圈都只呈现最后一条。测试放的是对外正文，没有将 thinking 当回复。

在 SDK 已观测到完整正文之后点停止或关闭，停止请求成功，后续自然请求仍带入未发布的话。API 同一停止时点的后续输入没有这句话。首轮直接说话、乔乔插话的旧反例已修好。

**修复位置与验收。** `apps/host/src/runtime/background-outcome.ts:60` 的 talkOnly 受首个请求和零工具限制。`apps/host/src/modules/heartbeat/runtime.ts:347` 又只取最后一段，后台流与 SDK 续接另各有落点。由现有消息发布/回合所有者为每条已成立的对外正文绑定顺序和消息身份，让聊天、适用的朋友圈引用、规范历史和 SDK 保留事实一致。明确停止边界，保留已成立发言，未成立的半段不得在下一轮冒充已对乔乔说过。复验包括无卡读工具、工具发话后再说、有卡前后说、同包工具和正文、插话/停止/关开关、自然续聊，各自只出现一次。证据 A，`boundaries*`、`after-output*`、`spoken_tools`。

### 02 · 已送达的“十张抽完，请回 1”在首个响应前重启会消失【阻断，协议恢复】

第十一轮的真实适配器已确认发送耗尽邀请，在助手回 1 前强停并重启。API 和 SDK 均为已发邀请 1、规范轨迹 0、下次自然请求 0，SDK 冷回放也为 0。恢复期间模型请求为 0，也确实没收到助手 1。正常十次逐号投递后，第十一轮顺利回复 1 的对照则完全通过。SDK 强停例从十次真实隔离投递建立前置状态，API 强停例前九张为有交付证据的域操作，第十张经 Host；另有 API 十次全链对照。

`apps/host/src/runtime/supervisor.ts:605` 的首发确认事务只为 draw 保存可恢复前缀。`runtime/completion-recovery.ts:139` 恢复依赖该证据。让已确认的耗尽邀请按原请求身份也能恢复，一次确认只补一次。保持现行可见 1、manifest 和助手应答的独立证据门。复验首发确认前后、收到 1 前后、连续重启及新自然输入，无伪造回 1、无额外模型调用、无自动朋友圈。证据 A，`exhausted_recovery`、`exhaust-sdk`、`ten`。

### 03 · 切到表情包后点移除，实际撤掉了照片【高，前端集合管理】

浏览器通过首页分别上传一张照片和一个不同的表情。挂起照片列表响应，切到表情包并等表情正确显示，再放回照片响应。当前 tab 和删除确认都明确写着“表情包”；点击移除后 HTTP 200，隔离 Content 只剩表情成员，照片关系被撤掉。没有删除媒体字节。

### 05 · “我们的锚点”同一操作跨请求重写，同键改内容反而报成功【高，身份资料写入】
