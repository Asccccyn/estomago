# 11 月 21 日独立复审四项修复

复审基线：`76c8117`；本批实施起点 `b44ff66`，协作分支 `unified-main-20261102`。原复审报告及观测脚本保留，未写生产数据、未部署、未 push。原先 README 其他人未暂存的两行不进入本批。

## 1. 已确认送达的模型协议在中途重启后延续

在原 `completion_recovery_json` 检查点内区分接受完成工具的证明与普通心跳工具包证明（`heartbeat_batch`），沿既有 API/SDK 执行边界登记实际观察到的完整助手工具包。真实工具通过准入后写入正在执行身份；收到回执后追加原调用 ID 的结果。记忆 hold 和自设预约在其既有权威业务提交事务中同时保存已经确认、尚未向模型派发的精确回执。无需新库迁移、新调度器或新回合。

Host 启动先恢复已接受完成的回合，再恢复仍在运行且没有提交轨迹的中断心跳。核对原 window/turn/attempt/run、检查点绑定原规范轨迹哈希和实际确认请求（以请求行身份和发送证据为准）。保留最后确认输入完整前缀，不读取朋友圈、源新版本或正文副本重造协议。仅补入仍未派发的原观察工具包；已确认业务事实及完整回执不重做，无法确定的执行如实标记 unknown，未开始的调用记录未执行。随后沿 `classifyBackgroundOutcome` 的原轨迹、manifest、outbox 与 run stamp 事务收口，不冒充正常完成或刷新保温活动时间。

如果强停发生在确认发送后、消费事件尚未记录，使用该原请求证明确认交付；若传输开始却无确认，则不把尚未送达的卡面带入后续自然聊天，保留原同 ID 未确认回执及 unknown 隔离。恢复后旧轮不再调用模型或重新抽牌。已经存在的历史终态不补写、不重放。

## 2. 预留话回应归属与重播

首次投影保存 `reservedReplyMessages`，只包含实际揭牌系统消息之后、同一 turn 的真实 assistant 消息固定引用。整轮已有发言事实保持原展示；揭牌前说话而其后沉默不产生首次回应重播资格。揭牌前后分别发话时，重播只含揭牌后的原观察修订。

历史投影若无显式回应子集，只有原揭牌消息和回应顺序仍可确证时才允许形成新重播候选；旧已冻结 numeric 引用若修复后会改变卡面则失效，不能默换。新重播修订基于原留言固定来源及固定回应子集，不因其他动作的迟到回执使 article version 增长而改变卡面。

## 3. 自设预约动作映射

`wake_manage` 的 schedule/update/cancel 接到现有 `BackgroundTaskService` 权威任务及幂等回执事务，分别记录设置、改期、取消的真实任务引用和 revision。组合真实 actor、房间、动作类型和业务操作键构造同身份摘要；同键重试只出现一次业务成功动作。list 是纯读，不记录设置；业务冲突/失败保留相应失败事实，不把用户代设旧任务改写为自设。

## 4. 客厅候选准入与历史读权限分离

受信扩展 adapter 的 enabled 定义为候选准入开关；枚举、认领选号及最终派发仍受它约束。已经交付的聊天卡及朋友圈经显式 history 读取路径，按源端当前读者权限、原 room/namespace 和固定 revision 解析，不再受参与候选的偏好开关影响。真正删除、撤权或旧修订不可读时如实降级，不返回缓存正文。
