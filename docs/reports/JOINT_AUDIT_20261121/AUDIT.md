## 十卡候选池的扩展接口

当前可复用 `HeartbeatSource` 的身份、命名空间、修订、权限范围，`HeartbeatSources.choose/resolve` 面向抽卡域的读取边界，以及 `HeartbeatCards.begin/claim/recordDelivery` 的消费账本。现有签名没有可登记的来源提供者；第七种来源会被反序列化白名单和数据库 CHECK 拒绝。隔离解析同形引用时，moments 通过，future_fixture、living-room、family 和通配符均被拒；这项是合同检查，不代表已有来源选择开关。把新功能伪装成 moments 或 memory 会混淆正本、权限和冷却。

最小变更是在既有装配根显式登记受信来源。每个来源负责有界枚举合格引用、解析固定修订和发送前复验，返回可用、删除、无权、版本不可读或暂不可用。抽卡域继续统一按来源、再按条目随机，按可信 identity 去重并结算，模型仍只选 1—10，不提交来源名。持久类型加法需迁移兼容旧牌、回执与旧窗。默认只有“我们”；“客厅”需要独立显式授权策略；family 无采集和候选接口实现。这里需要的是应用内部端口，当前需求不要求面向任意调用者的 HTTP 注册端点。

验收时在隔离环境登记第七个合成来源。关闭时零读取；开启后进入候选、按修订交付，编辑/撤权/删除不能换牌或越权。与旧来源同一可信 identity 共享冷却，未知状态跨日隔离，重启、重传和朋友圈都复用原账本；调度器、号码数和普通聊天工具面不用调整。该条件目前未满足。

## 后续范围：普通聊天自由抽卡

当前新 direct 窗的冻结工具名单有 heartbeat_draw，收到名称不等于有调用资格；普通聊天的动态发现/执行受 canDrawHeartbeat 限制。deferred 只暴露该用途下合格的定义。系统何时自动发起心跳，另由开关和调度门决定。当前未提供普通聊天实际抽牌，本次不计缺陷。

如后续批准，保留同一份每日十卡和来源适配，在宿主用真实 turn/attempt、会话和来源绑定新的合法入口。将每逻辑回合一张、跨入口同一号码唯一认领放入抽卡域同一事务，以操作和真实交付证据恢复；不要伪造 backgroundRunId。普通会话没牌时给耗尽或暂无合格号，原聊天继续。普通抽掉最后一张会使**下一次心跳**走回 1 的兜底；普通聊天本身不要求回 1。抽卡不推进真实聊天时间，实际发言按发布规则推进。预算、完成、取消、来源权限及家庭分层沿既有门。朋友圈若记录普通抽牌，应绑定真实聊天 turn 与同一事件身份，避免一个事件产生普通和后台两篇。

目录在新窗冻结时一次加入/改用途说明，旧窗自然滚动。已有直接定义和两个发现入口可以复用；本次实测 deferred 单个 draw 定义回执 342 B，现行 direct 已提供定义时确认回执 96 B。尚未实现未来合同，无法给出其精确字节增量。待乔乔与林石见裁定的是是否开放普通聊天、普通抽牌在朋友圈的展示范围，以及适用的回合预算；无须新定时器，也无须开放客厅或 family。
