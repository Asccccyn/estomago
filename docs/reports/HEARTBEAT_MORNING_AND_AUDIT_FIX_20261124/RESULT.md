按《Gemini 执行稿》1.1 接手 Antigravity 留下的本地工作，协作基线为 `unified-main-20261102` 的 `7ad961f`。实现提交为 `da165dd`。用隔离库、假时钟、真实 Host 与 Content 路由、模拟模型和 Mariposa 媒体边界验收。第 10 项保留待裁定的跨仓持久化问题。

## 晨间机会与交付边界

晨间沿一个心跳调度执行位和同一份预算，以会话、上海业务日组成唯一的晨间机会。领取后若首发前有新聊天，旧尝试以零派发收口并释放机会键，按最后正式聊天的时间重新安排。同一目标到期时晨间和普通保温共用一次执行。已经发出或传输结果未知的尝试保留证据。次日使用新的机会。两条模型传输路线在首发和续请求边界复核，会向已接纳的聊天和有效通话让位。已保存的语音或作品与已正式发布的聊天分别记账。

| 上海时间的前台事实 | 隔离验收的晨间首发 |
| --- | --- |
| 07:11 起没有真实聊天，包含昨晚晚安、隔夜冷缓存或凌晨续聊 | 08:00 一次，08:50 无衍生首发 |
| 最后事件在 07:10 或 07:10:59 | 08:00 |
| 最后事件在 07:11:00、07:11:30、07:20、07:40、07:50 | 依次为 08:01:00、08:01:30、08:10、08:30、08:40 |
| 07:09 用户发话，07:12 正式回复 | 08:02，设置接口返回回复时间作为顺延依据 |
| 07:50 只开页面 | 08:00 |
| 07:11、07:40、08:20 连续真实聊天 | 原目标均零首发，09:10 一次 |
| 08:00 先接受用户发言，08:00:05 正式回复 | 08:00 零首发，08:50:05 一次 |
| 08:00 已领取、模型首发前 HTTP 接受新聊天 | 旧尝试零派发，08:50 同一机会首发一次 |
| 08:30 目标后服务恢复 | 08:39:59 可以首发，08:40:00 已过期 |

夜间普通保温四个对照是 22:50 可派发、明确晚安后 22:50 零派发、23:00 零派发和 23:01 零派发。迟到上限按原有一小时缓存寿命与 50 分钟保温间隔之差取 10 分钟，以最新有效目标为基准。页面从 Host 读取预计时间、顺延依据和运行来源，不按本机时区重新排程。模型提示显示实际上海时间，例如顺延后的 `09:10`，并给出说话、在可抽条件满足时抽牌、安静结束的选择。卡源不足或当天十张已全部交付时说明本轮不能抽牌，晨间继续保留活动机会。

## 抽卡和朋友圈

新窗默认常用入口是 `heartbeat_draw`。直连请求检查带 `card_number` 的原生工具，按需请求检查常用说明和正式 `tool_invoke`。关闭客厅后，`tool_define` 与精确 `tool_catalog` 查询的动态余号与管理页一致。旧窗继续读冻结定义，可经原发现流程抽卡。正式卡面续请求携带固定来源，模型实际收到的预留留言图像按已确认投递记账。

| 发布内容 | 聊天 | 朋友圈主体与首次回应复抽 |
| --- | --- | --- |
| 要牌时的“我先把杯子放好” | 保留在稳定气泡 | 不收录 |
| 揭牌后工具发言 A、B | 按正式发布各一条，B 同操作重试无新增 | 卡面之后依次收录 A、B |
| 揭牌后自然回复 C，含换行和 emoji | 追加在原自然气泡内 | 只引用揭牌后的 C |
| 安静结束 | 无虚构消息 | 卡面及真实动作仍可读 |

新投影使用已正式发布的固定修订与码点范围，Host 展示与首次预留留言回应复抽共用解释。迁移前的投影仍按原可信记录读，重启补投影只依据已记录的证据。部署时先切 Content，再切 Host。旧 Content 在写入时会丢弃新增 `speech` 字段，不能用来接收新 Host 投影。旧 Host 读取新投影时能看卡面和确定属于揭牌后的完整消息，部分气泡用安全降级而不展示，避免引出揭牌前文字。

## 第 10 项的决策边界

隔离 Host HTTP 用例中，第二张上传失败返回 503，聊天消息为零，第一张已写进模拟 Mariposa 的正本。原键重试后按预期只发布一条正式消息。已有同哈希正式引用的对照仍可读取。真实 Mariposa 源码的 `upload_finalize` 按哈希登记全局对象，清理器只清未完成的上传暂存。E 现有协议无法证明某个已完成的哈希可以安全删除。

建议的最小协议是由 E 持久保留上传批次与原操作键，M 为本批对象保留可查的操作身份以及待确认的引用租约。重复请求从同一身份恢复。E 正式发布后确认引用。要回收，M 需查明 E 已放弃发布，并验证没有其他正式引用和未结束租约。回执丢失或 E 暂不可达时保留对象，等对账确认。M 的终态设计要覆盖两处断点：M 已落正但 E 未发布或收不到回执，E 已发布但 M 尚未收到确认。另一种选择是继续按现行合同保留该少量残留。仅加整批预校验或按哈希删除均不能安全解决此窗口。
