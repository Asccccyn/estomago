# 不可改动的裁定 · 单一执行口径

优先级：用户后续明确裁定 > 本文件与本包当前卡 > 已核实且未被替代的现行业务合同 > 历史规格/旧测试。代码事实不等于产品意图；遇真正冲突，记录受影响项，不由 Flash 选择最容易通过测试的一边。

## 设计与范围

D01. 采用“宿主稳定内核 + 本地能力模块 + 显式组合流程 + 既有外部适配器”。模块可在同进程，不要求一个模块一个服务。
D02. 本专项重构 est 的接入/组合/生命周期边界，不重做外部服务算法，不建设未来情绪产品。
D03. 既有 HTTP/MCP/流接口按已核合同保留。外部 HTTP 独立不代表宿主内部已解耦；MCP 不是解决所有编排的替代品。
D04. 静态显式注册即可。禁止扫描任意磁盘目录加载代码；禁止依赖注入容器、全服务 locator、动态插件市场和新的依赖管理器。
D05. 新能力允许改模块文件、声明式装配、配置叶子、路由声明与 UI。禁止承诺“以后任何需求绝对零核心改动”。真正新基础能力须单独定义合同，不能在专项里偷偷扩产品。
D06. 组合流程允许调用多个已授权公共能力。普通业务模块不得导入兄弟模块内部实现；跨域组合放 application/ 对应业务文件，不建一个全能编排大类。
D07. 宿主拥有消息/修订、模型回合、执行互斥、窗口与轨迹、权限准入、费用和取消；这些不各复制一份到模块中。
D08. 沿用单一会话串行链，不新增第二条后台聊天队列，不让持有执行位的工具等待同一队列里的下一回合完成。

## 用户语义

D09. 自动浮现为当前用户消息修订的同轮补充；不得改成后台下一轮漂移。展示为已批准日期/正文，不自动改成摘要；关系/原文详情与授权保留。
D10. 未提交/未发布草稿不是模型可读正式聊天。用户自己做上传/转写准备，不代表char获得读取权。已发布消息引用、会话归属及撤权仍需核验。
D11. 自动唤醒是char明确预约，不新增随机自然醒。醒来后可使用该回合获准的工具，不另做禁工具后台执行器。
D12. 心跳默认维护提示及纯“1”处理沿现行合同；不恢复零工具、单请求、固定128输出限制。实质发言/工具行为沿既有正式发布与轨迹链。
D13. 旧窗口工具目录与请求历史冻结；添加模块不原地改写旧窗口 schema、定义 ID、顺序、system 前缀、已发送正文。
D14. 保留既有 1h 缓存政策、用户手动换窗/原文选集和当前容量裁定；不从旧文档复活 64k/旧 hold 规则。阈值使用现行配置与最新裁定，不在本包硬编码另一套。
D15. 保留 OpenRouter/DeepSeek/SDK 当前能力差异与 blocked 状态。接口统一不等于所有驱动已经实现；不顺手解锁 SDK 桥。
D16. 不更改当前工具名称、参数 schema、属性插入顺序、参数默认语义、可见结果及已发布 HTTP/SSE 合同。结构迁移先做到等价；新业务另案。
D17. 保留记忆写入/来源绑定/引语逐字核对/召回续查/否定续查/详情三层/删除审批。情绪分析不得自动写成事实、人格或正式记忆。
D18. Siren 处理音频/通话；oído 处理声音证据。实时说话不能强制等待 oído、embedding 或第二个 LLM；声音证据不等于确定情绪结论。
D19. JSON 瘦身为接口边界：内部状态、模型投影、前端投影分开；不把完整执行上下文和调度 JSON 给主模型。不删除下一步操作确实需要的 ref/cursor/version。
D20. 控制生命周期与数据面分离。实时音频 chunk 不经通用业务事件系统落库；语音输出抽头保留同源正文与代际取消。

## 实施纪律

D21. 保留已有 guard、账本、幂等键与结果未知语义；不因为“不是极端测试”而削掉真实会收费/重复发消息的保护。
D22. 新建 registry 必须立即接一条真实 Host 路径。无消费者注册表不能交付，已删除的无头 MCP 实现不复活。
D23. 同一能力只保留一条生产执行路径。分批迁移时允许新模块和“尚未迁的旧能力”按不相交名单共存；同名双路或失败自动回退旧实现禁止。最终旧业务分支归零。
D24. 纯重导出/旧 import facade 可以短期存在，但不得含业务逻辑，不得无限期叫“兼容”；在迁移矩阵登记消费者与删除批次。
D25. 不把全部仓库状态暴露给模块。模块只拿窄服务接口；自己持有的仓库可用本域/接入表，不能直接读写其他域表。表的物理数据库可仍是同一个 SQLite。
D26. 声明式新增配置/装配是正常变动，不得为追求核心零 diff 建隐藏注册魔法。配置默认保持现状。
D27. 权限、预算、超时、取消仅由可信宿主注入，子调用可收窄不可扩大。Readonly 类型不是安全沙箱，必须保留实际检查。
D28. 一个组合操作只按既有收费边界预占/结算一次；根调用与子调用不得重复扣费，也不得通过组合隐藏下游付费。
D29. 根操作身份稳定；各有副作用步骤使用稳定、不同的步骤幂等身份。未知结果先查询原回执，不能从头重跑整个组合。
D30. 不新增全局工作流持久化引擎或跨库事务。现有回执/outbox/任务表足够的地方直接复用；不足只阻塞需要它的真实能力，不先造一套未来平台。

## 测试与复核

D31. 普通流程、常见中断、已有安全不变量属于本次必测；随机损坏库、大规模并发、无入口可达状态、未来未实现功能不属于本次。
D32. 先复用当前有效测试。旧混合文件先分类/拆分再跑；不得用已知矛盾夹具强迫代码兼容错误语义。
D33. 不以 PASS 数、行数或文件数验收。不设“所有函数80行”式机械拆分指标。
D34. 不更新 golden 来掩盖变化。固定时钟/ID只可消除测试技术噪声，不得规范化掉正文、角色、工具顺序、修订与权限差异。
D35. Flash 不签独立复核。GLM5.3 与 Astra 先各自读冻结提交/同一交付，独立形成结论，再对照差异。
D36. Codex 若被另行邀请，严格执行本包测试范围；无权为了更多测试恢复历史错误语义或推动无产品依据的重构。
D37. 最终状态分开：源码完成、离线合同通过、本机隔离联调、真实收费链、生产生效。没有执行的一律 NOT_EXECUTED/BLOCKED。
D38. 不要求用户每步确认，不越权自动发布。局部阻塞不伪装完成，不传播成整项目毫无意义的大停工。

D39. 保留当前通话 memory_only 精确能力政策：并不是“只有名字以memory开头的工具”。允许现行记忆/来源/episode/只读计划、轻量oído analyze/get/capabilities、发现机制与call_control；不恢复重型oído view/find/compare、唤醒管理、内容/星星/媒体检索等通话热路径。精确清单见tool-ownership里的memoryOnlyAllowed和源码1368附近。模式过滤影响模型catalog/define/invoke与最终执行检查，不重写窗口wire工具快照；UI/宿主控制仍按各自可信入口授权，模型不得自报turnId=null来绕过。
D40. 费用模块化不得新增前台聊天价格门。报价/预占只在既有背景或明确付费准入边界需要时执行；普通前台能力不能因为用户未配置背景报价而被新registry普遍阻断。不得把“每项有费用policy”误实现为“每次调用无条件查背景预算”。
