# 集成、退役、发布候选与回退

## 本次默认只交候选

不修改源工作树、不合入他人WIP、不push、不重启、不发布、不改生产flag/TTL/模型。不发送真实聊天，不使用真实外部收费服务。

## 最后集成顺序

1. 确认专项工作树只包含本人改动；提交列表与P卡一致。
2. 重新读取来源集成树的HEAD和状态。源树如果推进，只列交叉文件/符号差异；不要自动rebase/cherry-pick解决业务冲突。
3. 若仍同基线，冻结专项候选SHA；若出现后续可明确机械吸收的小改动，先在自己的候选树核对后作为单独批次，保留差异说明。冲突语义不自裁。
4. 对候选跑类型检查、已分类定向集合、架构边界检查；前端代码触及时做相应typecheck和一次构建。
5. 两位复核者读取同一SHA、报告与用例，不依赖Flash口头自述。
6. 返修只在对应卡/明确发现范围内做，完成后复核同一候选；不边审边悄悄换HEAD。

## 旧路径退出清单

- host-tools中业务工具name分支、业务SQL/HTTP/费用白名单/投影分支迁出，通用执行器不再认识业务工具名。
- 每个工具只从一个模块声明定义/执行/投影/费用；目录/初始可读定义引用同一来源。
- messages不直接认识SurfacingService/keepwarm业务；同步事务挂点和afterCommit不丢。
- Supervisor不直接判oído具体工具名或持有原始MariposaClient；现有runtime基础责任保留。
- app-context中的后台业务流程移到相应application用例；显式装配允许保留。
- HTTP领域分支调用对应领域服务；不能把原http.ts整段挪进单个`routes/all.ts`。
- 旧wrapper如果还被测试/内部import引用，替换消费者后删；确需历史兼容者登记“非双业务实现”的理由与退出批次。

## 发布前另行核对（本包不执行）

实际运行服务路径/配置/Node；新候选artifact；数据库迁移是否真的必要；现有窗口快照与生产数据备份；服务生命周期停止与启动；无需收费的健康检查；小范围真实交互由用户另行批准。

本专项原则上不新增业务表。确需接缝字段时先说明现有表不足、迁移对旧数据/旧程序的影响；不能把破坏性schema改动夹进纯重构。

## 回退

隔离施工阶段：以自己的阶段commit为回退点，在自己的worktree修正或revert；不对源树reset --hard。
发布候选回退：保留旧候选代码和构建物；如有新schema必须确认旧程序可读取。不得通过删除window_toolsets/聊天/回执来回退。
真实外部副作用不随代码回退撤销；本包默认没有真实副作用。

## 本次遗留能力边界

通用外部MCP客户端、SDK工具桥、未来情绪算法、新语音供应商不属于本专项已完成范围。新模块接口对这些保留合适接缝，不用生产空壳冒充实现。
