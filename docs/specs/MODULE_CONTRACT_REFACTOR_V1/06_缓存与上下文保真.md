# 缓存、历史与上下文保真：专项红线

这次改变代码组织，不改变char实际看到的话、已见工具定义或历史。不能通过真实收费模型请求验证本专项。

## 迁移前要采集的离线对照

在独立test home、合成但正常可达的会话中，保存：
1. 新窗首次普通聊天的工具目录、wire工具数组、定义ID、初始可读文本与实际待发送payload。
2. 同窗第二条消息与一轮工具续调用的payload/轨迹。
3. 同轮自动浮现的当前message/revision/window绑定、模型正文、必要详情ref。
4. 一次自主唤醒和一次纯保温回执/实质活动的请求及发布结果。
5. 已发布语音引发的正文投影/音频引用，及通话正文抽头不复制请求的证据。

固定可注入时钟/测试ID；不使用真实对话、身份或密钥。snapshots放测试资料，不是生产备份。

## 必须逐项保持

- 旧window_toolsets、catalog_json、wire_tools_json不因新代码装配而重新生成。
- `freezeWindowTools`优先读旧快照/已发送证据；不清空表来让迁移通过。
- `definitionId`以原定义序列化为依据；不得先排序properties再说“语义一样”。
- `definitionWasSeen`继续查真实发送请求，不以调用过define、启动时知道schema、DB里有定义冒充模型已见。
- 同窗系统前缀/工具集合/历史append-only规则不变。新模块不强制旧窗立即获得新能力。
- bootstrap快照与同轮贡献分开；不能每个模块各重建一个system块。
- OR/DS的角色、reasoning继续态及最终wire守卫沿当前集成树，尤其保留849b1d5的错误语义收敛结果，不从历史包恢复另一套。
- 自动浮现严格同轮；retry/edit/stop都能使旧准备结果失效；frozen已派发内容不被新查询覆盖。
- 模型投影只在规定边界做一次。模型精简JSON不作为内部CAS/账本回执使用。
- voiceTap沿真实生成文本与fence；不增加第二次LLM请求“专门为电话写文字”。
- 现有当前阈值、TTL、工具预算、恢复顺序与人工换窗策略不调整。

## 对照失败怎么处理

先分类：A技术非确定字段；B预期的路径重命名；C模型可见/业务改变。
A只允许在测试固定时间/ID，不宽泛清空字段；B不能影响wire；C立即停止该迁移步骤，找到差异来源。禁止开启ESTOMAGO_UPDATE_GOLDEN一次性更新全部样本。

新的布局若无法保持现有历史语义，应回退本步候选修改，不动用户生产窗。需要产品迁移的新语义单独列出，由复核者/用户决定，不与本专项混合发布。

## 声明限度

离线payload一致可证明本地组装合同未变，不能证明远端一定缓存命中。真实服务状态、真实供应商缓存命中、真实通话延迟与生产生效均不属于本包生成时已验证内容。
