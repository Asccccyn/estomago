# 接口合同与执行算法

`contracts/reference-contracts.ts` 是可检查的类型参考，不是可直接覆盖整个仓库的补丁。复制现有 ToolExecContext/Result 到叶类型时保留实际字段；不要为了贴合示例删掉 seenMessages/imageRefs/attemptId 等现有语义。

## A. 能力声明：模型描述与内部元数据分开

每项能力由所属模块提供：固定能力ID、当前模型工具定义、参数校验、实际handler、模型投影、权限策略、费用声明和需要的依赖。模型只获取当前工具定义，不看到实现函数、费用上界、内部操作键、权限域、重试策略。

工具定义来源必须单一：catalog、define、初始可读工具、invoke验证，都从同一冻结定义获得。48个本次静态业务工具的基线顺序见 `contracts/tool-ownership.json`；不是当前窗口一定全暴露48个。3个deferred入口继续按既有协议。

**不要按模块分组后改变原目录顺序。** 每个定义携带仅宿主使用的 baselineOrder，聚合时沿该顺序。新功能将来追加或有明确新窗策略；本批不重排。属性插入顺序也不随意重建，否则JSON和definitionId可能改变。

## B. 一次模型工具调用的固定顺序

```text
读取该window的冻结工具快照
→ 解析catalog/define/invoke并检查已见定义（保持当前行为）
→ 解析真实业务能力名，不把tool_invoke当收费业务
→ 使用该窗口的实际冻结schema校验参数
→ 构建宿主可信调用上下文，去掉模型自报的内部字段
→ 执行可见性/权限/取消/期限检查
→ 依据可信费用政策做一次准入或从既有预占中分配
→ 发出原有tool start生命周期事实
→ handler（或已批准组合流程）
→ 处理真实回执/副作用/已见增量/图片引用
→ 对结果执行所属模块的模型投影一次
→ 原有tool result/error事件
→ 原有工具循环序列化/继续模型请求
```

若现行执行器在 start事件与准入次序上有更严格已验证合同，先记录并沿用，不能以这张图改变用户可见行为。关键要求是：任何实际外发/写入之前准入；失败不变成功；投影不能先于内部记账；同一操作不双执行/双计费。用迁移前后的事件轨迹对照确认。

错误码沿用现行。只有确实不存在可表达的新架构错误才新增少量稳定内部错误码；不要全项目替换错误对象格式。

## C. 内部组合调用不是伪装模型调用

模型调用需要“定义实际已见”；宿主执行已批准内部步骤不需要伪造 tool_define。二者共享可信权限、取消、计费边界，但分别进入模型桥与内部端口。

内部端口必须在装配时显式提供。例如 voice-hearing 只拿 `PublishedAudioReader`、`HearingAnalyzer`，不拿 `registry.invoke(anyName)`。不能把原始adapter直接暴露给所有模块从而绕过执行政策。

内部调用上下文由宿主创建：actor、conversation、window/turn、input revision、root operation、signal、期限、账本关联。模块不能从输入JSON覆盖；子调用只可收窄可访问资源/期限，不能自行扩大预算。

现行ToolExecContext的seenMessages/seenSequence必须来自真实已发送请求，不得从数据库最新位置猜“模型看过”。

## D. 去掉全局rawToolCallId状态

当前 `rawToolCallIdRef.current` 是工具调用身份的全局可变桥。提取执行器时，工具调用ID从当前参数兼容读取后立即放入本次ctx；handler只读ctx。`__tool_call_id`仍不能变成模型可随意声明的权限/身份。

迁移：列出rawToolCallIdOf所有消费者 → 改显式ctx引用 → 保留原operation派生算法 → 对普通工具续轮和一次重试验证键不变 → 删除全局变量。不要以“现在串行所以没事”继续扩散该模式，也不为此制造百线程测试。

## E. 同步生命周期挂点与事务

消息服务产生稳定事实，如 accepted/revised/published。事实携带现有messageId/revision/conversation/sequence；模块在自己的受限订阅中登记任务或活动投影。

`inTx`处理器必须同步SQL-only，使用调用方既有事务连接；不调用HTTP/模型、不自己嵌套事务、不返回Promise。`afterCommit`只负责唤醒已经持久登记的工作，不作为唯一事实来源。

**本批不发明新的通用事件存储。** 保留已有surfacing job、archive outbox、activity表及其幂等。现有SSE EventService是前端回放面，不自动成为内部可靠任务总线。订阅顺序显式固定；有依赖的步骤按命令流程，不靠注册顺序巧合。

用户普通编辑、HTTP编辑、route edit、retry修改均必须覆盖。禁用可选模块时，不登记该模块作业，但消息主事务仍有效。必要系统不变量失败不能被统一吞掉。

## F. 两种上下文贡献

`window-open`：身份/开窗资料/初始工具等既有有限快照。沿用旧窗缓存，不逐轮重建。
`before-turn`：自动浮现等绑定当前输入的贡献。准备→同轮复核→实际派发前准入→冻结已发内容→随本轮结果保留，顺序照现有实现。

贡献者提供的是业务正文及必要引用，不是一份随意修改messages的函数。宿主负责最终角色、插入位置、预算、provider差异、hash/轨迹和权限重检。模块不能拿可变的整个历史数组。

接口需保留现有 `reuseFrozen / augmentFor / finalAdmit / markDispatched / markRetained / cancelForTurn` 的实际语义；可以换中性名称，但不能只留下prepare而漏掉其他生命周期。对同轮消息修订失效，不允许拿旧结果“凑着注入”。

## G. 生命周期与程序事实请求

模块可声明必要start/stop钩子；Host按明确依赖顺序启停。已有oído删除重试、浮现worker、调度器都迁入实际生命周期，不新增重复timer。

程序事实请求只接受并持久化、安排同一执行链，返回accepted/原回执；不等待新回合完成。`submitProgramFactTurn`不得被模块直接持有整个Supervisor调用。

可以提取窄ProgramFactsPort及其现有持久化实现；组合根在启动前显式绑定唯一执行消费者。少量受控的启动绑定不是循环依赖错误，关键是不暴露整个Supervisor、不在正在执行的同会话中等待后继轮。**不要为了消灭所有回调而重写actor系统。**

## H. 注册表应做的事与不应做的事

做：确定性枚举、名称唯一、已配置实现查找、显式缺失拒绝、可替换测试实现、用于架构检查的声明清单。
不做：业务数据库查询、跨服务重试循环、动态刷新旧窗口、自动发现远端新工具并授权、万能fetch、自动降级到旧handler、通用DAG执行。

## I. 引用与资产

音频/图片使用现有资产引用，不复制原音频到工具JSON。访问由所属会话及已发布绑定核验；内部模块拿引用不是自动拿权限。oído返回视图、imageRefs、分页cursor按现行模型/前端边界保留。

模型投影可以删内部元数据，但不能删下一步需要的analysis_id、memory_ref、cursor或写操作所需版本。本专项首先迁移现有投影，不顺手改业务输出字段；确需瘦身差异单独列清单让复核者判定。

## J. 本轮发现的通话模式政策：不能漏迁第三份硬名单

集成树host-tools:1368–1382的MEMORY_ONLY_TOOLS是当前已经落实的产品政策，不是本包发明。把每项已批准的通话可用资格放入对应能力的宿主元数据，通用模式判定接收当前会话的可信状态；不能在executor里继续维护一串业务工具名。

同一个模式判定同时用于catalog响应过滤、define准入、invoke解析后的真实能力以及执行前最后检查。冻结的wire_tools_json与definitionId仍不变：模式禁用是在使用时阻止，不是原地删定义。模块注册/开关不自动扩大通话白名单。

被用户暂时关闭的模块，旧窗口可能仍有冻结定义；这不代表有执行权限。沿现行能力不可用错误拒绝，不改历史、不回退旧handler。

报价的调用时机要照搬当前admitBackgroundTool：背景run缺必要准入应拒绝；非背景不因新接口强制要求背景报价。新接口政策存在≠每个场景都启动全部政策。

动态mood词表建议由模块提供 `definition()` 工厂供**新窗口目录构建**使用；已经冻结的窗口继续读取数据库原spec，不能重新调用factory重建已见定义。definition工厂不得自行联网；词表刷新仍按现有受控策略。
