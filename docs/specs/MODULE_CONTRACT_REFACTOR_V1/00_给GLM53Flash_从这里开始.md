## 任务一句话

让现有能力真正经稳定接口进入 est：普通工具、跨模块组合、消息生命周期、当轮上下文、自主唤醒共用既有宿主基础设施，而不是每新增一个能力就在消息核心、Supervisor、工具分发器和 HTTP 总入口添加业务专属分支。

**不把模块化理解为“禁止协作”。** Siren 与 oído 可以配合；自动唤醒可以使用其他工具；未来情绪模块可以依赖获准的记忆读接口。禁止的是越过公共接口读取别人内部状态、绕过权限/费用/取消、同步互相回调导致死锁、共享可变业务正本。

## 连续执行规则

一次领取全部工作，但每个子步骤只解决一个明确问题。每个子步骤后：检查 diff → 类型检查 → 对应定向测试 → 写进度 → 再继续。

不用每一批问用户“继续吗”。只有下列情形阻塞受影响子步骤：基线无法确认；需要新增权限/业务裁定；真实外部合同不足；越出本仓写入；需要部署/真实收费；两次有证据的定向修复仍未定位根因。记录在 `BLOCKERS.md`，继续不依赖该阻塞项的工作。

不得通过放松断言、扩大 allowlist、把异常改成成功、加无依据默认值来“修好测试”。不要反复全量跑测试撞答案。测试失败先给出一条可核实的原因和最小改动，不能一次猜改五处。

## 明确禁止

- 不推倒聊天宿主；不重写 Mariposa/Siren/oído；不新增插件市场、热加载、Redis、工作流 DSL、通用服务发现器或万能 HTTP 工具。
- 不将所有功能改成 MCP。HTTP、实时音频流保持合适的原接口；本专项不是补齐通用 MCP/SDK 工具桥的项目。
- 不将业务修改混进结构重构；不改模型/供应商/缓存 TTL/换窗阈值/记忆语义/心跳自由度/输入键行为。
- 不直接运行 `npm test` 的整个旧集合；先完成实际场景分类，再按明确文件选择器运行。详见测试政策。
- 不创建脱离产品可达状态的极端夹具，不做百万消息、百线程竞态、随机数据库损坏等压力扩展。
- 不删必要的普通权限、取消、幂等、停止后迟到结果和缓存连续性验证。
- 不直接改生产配置、生产数据库、LaunchAgent、凭据、隧道；不调用真实 Opus/OR/JEV/ASR/TTS/embedding。
- 不在用户源工作树执行 reset/clean/stash/rebase，不把别人的 dist 改动带入自己的提交。
- 不用“文件存在”“注册条目存在”“类型通过”“模拟 transport 通过”冒充生产接通。
