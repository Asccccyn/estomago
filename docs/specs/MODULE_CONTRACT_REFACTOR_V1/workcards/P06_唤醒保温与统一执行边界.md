# P06 · 唤醒保温与统一执行边界


## 目标
调度器只知道任务与执行状态；主模型工具循环只知道通用能力接口；唤醒可以组合调用其他模块而不写第二套runner或费用体系。

## 源锚点
BackgroundTaskService、BackgroundScheduler、background-settings/policy/ledger/tool-cost；app-context内executor.executeRun；Supervisor.runBackgroundTurn/runOrToolLoop/runSerialized；Host恢复链。

## 子步骤
P06.1 把app-context中的后台executeRun用例移至application/background-execution。依赖仅任务设置读取、正式提醒发布、单会话执行入口、逐派发记录；不把整个Host对象传入。
P06.2 保留同一runSerialized执行链。后台目的/任务状态属于宿主公共运行合同，不必为了“核心不能认识任何类型”删除purpose枚举。用户停止/睡眠窗口/让位/预算门沿现行位置复用。
P06.3 Supervisor.runOrToolLoop统一调用capability executor，不调用业务分支。awake/keepwarm使用同一窗口冻结目录和工具可见性；不新建BackgroundToolExecutor。
P06.4 费用准入以真实业务能力解析结果做一次。tool_invoke和nested步骤不双扣；报价未知沿现有错误拒绝，真实免费证据不扩大。按05的两种计费情形映射已有ledger，不造新引擎。
P06.5 子调用接同一个AbortSignal/截止时间与run归属。关闭开关后后续可取消步骤不发；已发生副作用保留证据。
P06.6 pure ACK“1”、非1文本、工具/发布等实质活动分类不变；不恢复旧零工具/单次封锁，不假装维护回执是双方聊天。
P06.7 程序事实轮使用窄请求端口，提交当前队列后继轮不等待其执行；消息/事实身份不混淆。保持现有拒接/取消回合幂等及普通聊天连续性。
P06.8 Host.start顺序保留recoveryPass先清理/释放，再recoverSchedule重派，再启动worker/调度；不得让模块新start钩子绕开该顺序。

## 验证
预约→到期→模型调用记忆工具→正式发布；保温只回1不入聊天；保温做实质工具行为仍正确；一次关闭开关/停止使后续步骤停；一条新用户消息与已排队背景轮按现行政策运行；费用一次预占/结算。

## 不做
后台任务泛型DAG、任意多级agent、随机自然醒、无限并发、真实付费验证、重写所有已有scheduler状态机。
