# P05 · 消息生命周期与同轮上下文


## 目标
消息核心不再直接认识浮现/保温业务；上下文贡献者通过稳定边界接入，但不损失同事务登记、同轮浮现与缓存冻结。

## 先读
04.E/F、06；messages/service.ts全部接受/编辑/发布；messages/mutation、retry、routing.service相关入口；SurfacingService完整交付生命周期；Supervisor实际装配/最终派发代码。

## 子步骤
P05.1 列现有动作表：首次接受、幂等重放补作业、普通编辑、route edit、retry edit、助手发布、修订发布、afterCommit。逐项写旧调用位置和效果。不能只迁首次发送。
P05.2 建MessageLifecycleHooks叶接口：同步inTx facts与afterCommit。把SurfacingMessageHooks具体名替换成通用事件；必须保留消息ID/修订/序号/hash/时间与“本次是否真实首次发布”的事实。
P05.3 在application/message-lifecycle装配浮现登记、编辑撤销、活动锚点等消费者，使用现有同连接事务。接入代码不得在tx中HTTP，不得await。已有归档outbox不重复登记；不新建中央event-inbox表。
P05.4 幂等重放保留“补缺失作业但不当新真实活动”的现行行为。提交后通知可以重复而业务作业必须幂等。进程重启仍用现有恢复扫描。
P05.5 建上下文贡献接口，至少区分开窗快照和当轮补充。把浮现的prepare/reuse/finalAdmit/markDispatched/retained/cancel实际行为映射到完整钩子；不能只迁一处augmentFor。
P05.6 Supervisor消费已验证的贡献块及内部handle，不import浮现具体业务类型或调用远端Mariposa。宿主仍控制角色/位置/预算/最终发包；OR/DS差异在实际transport投影边界，不让每个模块改历史。
P05.7 当前输入编辑/停止/换窗后旧贡献失效；已派发冻结块保留不改；无贡献与贡献失败仍沿现行可选降级，不污染主聊天。
P05.8 BootstrapPort收口开窗资料，复用已有完整分页/失败规则与当前允许的部分加载政策；不在本专项自行改“整包失败是否注入I”等业务裁定。

## 验证
一次正常同轮浮现；一次编辑后旧准备作业不使用；重试不重复登记；两条真实消息之间活动锚点正确；一次普通断连重放不把已完成轮复活；旧窗prefix逐字对照。

## 禁止
把所有事件改成异步event emitter；消息先提交后才不可靠登记任务；下一轮补浮现；模块拿整个可变历史数组；以简化接口为由漏掉finalAdmit/取消/冻结。
