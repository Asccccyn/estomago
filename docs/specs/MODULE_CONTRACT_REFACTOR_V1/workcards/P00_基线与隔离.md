## 执行步骤
1. 对02中的集成来源执行只读preflight，记录完整SHA、分支、dirty路径、Node。
2. SHA仍为849b1d5时按该提交开工。若只是后续正常提交，读与本包锚点相关的diff，写“基线推进清单”；不自动退回849、不自动忽略新修复。若新的工作树/合并基线不明确，暂停修改，交BASELINE_BLOCKED。
3. 当前只有两项dist未提交时，记录并留原地；不stash，不copy覆盖。若实际新增生产源码WIP，先区分在途改动；未提交源码会影响本专项的，停止该范围，不以旧提交冒充最新基线。
4. 新建隔离worktree，建议路径与命令如下。路径已存在则检查，不能强制覆盖。

```sh
SOURCE="$HOME/Projects/devspace-workspace/worktrees/estomago-integration-20261024"
TARGET="$HOME/Projects/devspace-workspace/worktrees/estomago-module-contract-v1"
BASE=$(git -C "$SOURCE" rev-parse HEAD)
git -C "$SOURCE" worktree add -b refactor/module-contract-v1 "$TARGET" "$BASE"
cd "$TARGET"
export PATH="/opt/homebrew/bin:$PATH"
node --version
```

5. 将执行包保存在工作树外或 `docs/specs/MODULE_CONTRACT_REFACTOR_V1/`（只复制文档/合同，不把示例TS自动当生产文件）。建立08指定报告目录。
6. 检查依赖是否已有。worktree不含node_modules时，按现有锁文件用npm ci安装到隔离树，不升级版本/改lock。网络不可用就BLOCKED依赖步骤，不借源树node_modules做未经记录的奇怪共享写入。
7. `npm run typecheck`，如果失败记录基线失败，不修无关业务。测试先按07分类；选择与第一条链有关的有效普通测试基线。
8. 复制模板为实际报告，将所有验收标NOT_EXECUTED；不拷旧PASS。
