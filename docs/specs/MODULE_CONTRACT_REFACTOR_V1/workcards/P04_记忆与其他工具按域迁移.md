# P04 · 记忆与其他工具按域迁移


## 目标
迁移所有剩余业务工具，保留工具语义和来源核证。工具所有权/顺序以contracts/tool-ownership.json为导航，按当前SHA核对。

## 迁移批序（每段独立验证后继续）
P04.1 conversation_read + chat_send_text/chat_send_attachment：归conversation公共服务。保留实际已见范围、中文码点切片、正式发布outbox、附件权限。不要让memory模块直接复制聊天SQL。
P04.2 memory_read_full + memory_recall/memory_recall_next：归memory模块。保留三层详情、已见ref、独立surface凭据、分页固定结果集、否定续查（66acb20）、find words目标等现行合同。
P04.3 memory_hold：整段来源核证/resolveQuoteRefs/receiptOf/未知写结果恢复搬入memory用例与所需窄conversation/archive端口；不改成简单HTTP透传。已见窗口视野不能由DB最新记录替代；引语与完整事件来源分开。
P04.4 memory_open/correct/deletion_review、I读写、plans读写、episode组：分别小步迁移。保留审批/版本/操作ID和模型投影，不一边迁移一边合并工具。
P04.5 动态mood词表/hostToolsCache属于memory catalog；装配的新窗快照取当前已验证词表，旧窗不刷新。把Supervisor的mariposaClient访问改为只取开窗资料所需BootstrapPort，不能直接拉出原始client。
P04.6 wishstar全部现行工具：一个模块工厂可提供各能力，保留每项权限/交换/通知与费用合同。不得因为同前缀给任意wishstar_*都放行。
P04.7 content_post_create/comment/posts_list、creation_save_artifact：归content模块；HTTP与工具共用原领域服务，作者从可信上下文派生；不新增内容后台。
P04.8 identity_milestone_write归identity模块，与Mariposa I分开；原版本与条目化语义保持。
P04.9 media_import/media_search归media模块；复用现有assets/index/embedding worker接口；不要绕过URL安全或收费上界。
P04.10 wake_manage/background_complete/context_review_complete只迁定义与handler归属；它们的回合编排在P06收口，不能为迁工具改变评审或唤醒政策。

## 每迁一个能力的六件事
定义移到owner → handler和业务数据归owner → model projector归owner → quote/权限policy归owner → 实际注册并通过Host调用 → 删除旧分支/名单对应项。

`model-results.ts`只能留下通用选择/失败映射或被删除，不能变成另一个全业务switch。现有其他工具已经独立投影的，显式声明保持该当前投影，不把raw回执全部透传。

`background-tool-cost.ts`把已核free事实与需配置报价移入能力政策。通用读取可信价格配置的函数可保留，但不能继续维护业务工具硬编码集合。

## 验证与停止
按07选择每组已有有效用例，特别hold-quote、recall、三层详情、工具发现与正常背景调用。任何意外模型字段/定义ID/顺序变化先停。外部合同缺少证据时只读兄弟仓核对；不写兄弟项目。
