# 给 GLM5.3：行为、组合与迁移复核

你是独立复核者，不是Flash的自审身份。先读00共同规则、01裁定、07测试政策、08验收、来源/候选SHA。

## 必查链

1. 从实际Host模型工具入口进入oído模块。已发布源→ingest→analyze→源绑定→模型投影；至少看到新路径被实际调用，旧handler没有继续处理。
2. 自动唤醒→当前窗口→一项memory工具→正式发布。相同工具不是另有后台拷贝；权限、费用、取消一致。
3. 消息接受/编辑/retry/route edit→浮现登记/失效→同轮最终准入/派发/保留。不能下一轮漂移。
4. memory_hold/recall/三层详情来源与seen合同不被“薄适配”掏空。否定续查保留。
5. 同一窗口迁移前后工具定义/顺序/ID/前缀/历史相同；旧冻结定义不被新目录覆盖。
6. 通话正文与聊天正文同源、stop取消旧代、程序事实轮没有队列自等待。

## 方法

先读处理器/调用点，挑07允许的代表测试独立重跑；必要时补一个正常可达场景，不泛化成压力套件。发现源基线已有缺陷标baseline，不把未引入的无关问题塞进结构专项。

特别检查已有测试删除/拆分理由：不可能夹具可以移除，发布权限、unknown回执、实际停止后迟到结果不能被借机删。
