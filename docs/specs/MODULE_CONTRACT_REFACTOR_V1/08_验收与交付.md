# 验收与交付

## 完成判据

本包所有P卡完成 + acceptance全部必需项有真实证据 + 独立复核无未处置阻断 + 旧业务接线退役。
源码测试通过不等于生产通过；交付时保持区别。

必须回答五个核心问题：
1. 新模块注册是否真正进入Host执行，而不是只有测试用？
2. 添加一个同类能力时，是否还要修改supervisor/消息核心/通用执行器的业务分支？
3. 跨模块组合是否仍保持授权、取消、费用、幂等和未知结果？
4. 冻结历史、当前浮现、原文读取和真实发布是否原样成立？
5. 旧路径是否删掉，还是在新registry后面又回到原来巨大switch？

## 最终报告目录

在隔离仓 `docs/reports/MODULE_CONTRACT_REFACTOR_V1/` 写：
- `BASELINE.md`：实际来源SHA、dirty说明、工作树、Node和原有阻塞。
- `PROGRESS.md` / `RESUME.md`：可续做进度，不复述长篇推理。
- `MIGRATION_MATRIX.md`：48工具+生命周期+context+HTTP，每项旧位置/新owner/真实入口/旧路径删除。
- `TEST_INVENTORY.json`：现有测试分类与排除理由。
- `ACCEPTANCE_RESULTS.json`：复制本包acceptance，填实际status/commit/command/evidence_kind/evidence_path。
- `CHANGE_LOCALITY.md`：两次实际“扩展演练”的git diff范围，说明声明性配置变化与业务算法变化。
- `MODEL_VIEW_DIFF.md`：模型工具schema/顺序/投影/两轮wire对照，无隐式改语义。
- `BLOCKERS.md`：未实现/未运行/需授权/兄弟仓缺口。
- `GLM_DELIVERY.md`：实现摘要、测试结论、旧路径退役、无生产操作声明、如何复核。

不另建几十份内容相同的证据文件，不要求用户阅读每条日志。报告中命令结果应能对应提交，不能粘贴旧分支PASS。

## 证据数据结构

每项验收使用 `NOT_EXECUTED / PASS / FAIL / BLOCKED / NOT_APPLICABLE`。PASS必须有actualCommit、命令或人工检查步骤、evidenceKind、相对证据路径。NOT_APPLICABLE仅允许复核者确认不适用，不能把没有实现写NA。

产品实时/生产项初始NOT_EXECUTED，永远不由文档生成脚本填PASS。自检脚本只能检查交付材料格式，不负责判断业务正确。

## 两项扩展演练

演练A：在测试目录增加一个使用现有已发布资产读取端口的只读探针模块，接入真实registry与Host fixture。从真实工具入口调用它。核心算法无需修改；允许测试装配声明。探针不进生产目录或默认工具集合。

演练B：把首条真实oído用例依赖的transport替换为合同兼容的fake实现，证明voice-hearing/宿主消息核心不改。再断开该可选能力，普通文字路径仍正常。仅证明接口可替换，不宣称真实声音分析效果。

未来情绪只作为测试消费者调用既有记忆读端口；不造生产空壳。上述演练不能替代真实oído/wake/surfacing迁移。

## 不合格的交付

只多了registry文件；大switch藏进新名字；仍有“legacyFallback(name)”；同名能力双注册；旧窗被重建；全套JSON给模型；timer/worker声明却没Host.start/stop；测试只有stub registry；报告只写N/N全绿；部署状态未分离。

## 阻断与建议区分

阻断：已批准语义被改、实际入口未接、重复收费/发布、未授权读取、同轮漂移、取消失效、旧路径重复执行、既有正常路径回归。
建议：文件还可更漂亮、理论未来抽象、未知压力下可能更慢。建议不在本轮无限扩大工程。

补充报告：`TEST_EVIDENCE.md` 汇总实际命令、退出码、候选SHA、覆盖的验收ID与未运行项；不要只写测试数量。
