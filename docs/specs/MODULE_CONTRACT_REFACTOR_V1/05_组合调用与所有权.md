# 跨模块组合：具体做法、费用与恢复

## 1. Siren × oído

### 已发布语音的深听

前提通过真实入口建立：上传合法合成音频 → 需要时由fake Siren完成转写 → 用户发送 → message/revision/asset绑定已持久化 → 模型收到该消息的可见audio_ref。

随后调用 `oido_analyze`：
1. 从当前ctx取得房间，读取已发布音频引用；确认asset/hash/权限。
2. 复用当前可信转写（有则带上；无则沿既有允许路径，不新加“必须先转写”）。
3. 调用已有oído ingest，使用原幂等与取消机制，保存原有receipt。
4. 调用已有analyze，保存分析↔源绑定，按当前规则在交付前重检可见性。
5. 返回现有model-view；图像引用沿imageRefs通道，不把二进制或全部内部状态塞进JSON。

该组合应放 `application/voice-hearing.ts` 或oído模块的显式用例；Siren和oído适配器不互相import，不直接读写对方数据库。现有 `oido_ingest_receipts / oido_source_bindings / oido_delete_intents` 是est接入映射，属于对应接入仓库，不要求远端服务直接访问。

### 转写准备与模型读取分开

用户可在发送前准备转写，服务可以有该asset的转写记录；`transcript_read`给模型的读取仍要求正式消息/已获准通话源。不得通过直接SQL写一条未发布transcript，再断言模型应该读到，来检验“分页函数正常”。分页本身可测纯函数，但业务读取测试必须有真实前置路径。

### 实时通话

音频流走现有流/NDJSON/WS合同，不改成每chunk registry工具。保留同源文本生成、voiceTap、播放取消、排队回合停止与生成fence。深听是按需旁路，不强制进入实时关键路径。本批不增加新音频供应商、不调参追求新延迟指标。

## 2. 自动唤醒 × 任意获准工具

`wake_manage`与HTTP管理面共用现有BackgroundTaskService。到期调度只做领取/取消/恢复/预算入口→提交给当前会话同一执行机制。

模型醒来后用当前窗口冻结可用工具。工具新能力不要求调度器新增`if(toolName...)`。背景上下文携带root run/费用/取消，所有步骤沿同一政策。

保温开关与自主开关继续独立。用户新消息到来、关闭开关、睡眠窗口、迟到策略均沿当前已批准实现。不存在“模块化后后台都能绕过预算”的例外。

## 3. 记忆 × 未来情绪（只留接缝，不建设新系统）

未来消费者只通过获准的记忆读取公共端口取得结果，不直接查Mariposa表；输出自己的分析状态，不覆写事件事实/I/心情。现在只用一个测试目录内的消费者调用当前真实记忆公共接口，证明不改memory模块内部即可消费。

这个消费者必须标为架构兼容性探针，不成为生产情绪模块、不形成新常驻任务、不宣称情绪功能已实现。若公共接口尚不存在，只针对现有读取能力提取，不编造未来数据schema。

## 4. 根操作、步骤与计费

### 唯一计费原则

先沿现行 `beforeBackgroundTool` / quote / ledger行为迁移，再把报价声明归属各模块。一个模型`tool_invoke`只准入解析后的真实能力一次，wrapper不重复计费。

组合有两种可实施情形，按现行事实选择并记录，不能自由混用：
- 现有该能力的可信上界已经包含整个下游路径：根能力预占一次，内部步骤在此范围内执行，不每层重复预占；账本保留真实费用回执。
- 新组合有多个独立付费根操作：每项通过既有准入边界分别预占并关联同一根run，不再额外把它们总和重复计一次。若缺少可信价格或现有ledger表达不了，禁止上线该付费组合，记录缺口；不要猜0或新增全套账本。

内部只读/本地也不自动等于免费。保留现行verified-free证据；报价是上界而不是权限或实际费用。未核实下游不能标免费。

### 操作身份

根操作沿既有tool_call/消息/任务幂等身份。内部不同副作用步骤使用确定的步骤键（如ingest、analyze）；重试同一步键不变，换步骤键不同。尽量沿用已经存在的派生算法与回执，不更改外部格式；若需改格式，作为合同变化单列而非暗改。

### 常见失败的处理

第一步成功、第二步明确失败：保留第一步成功回执，只重试被允许的第二步。
第二步超时且结果未知：保持unknown，查询原receipt/状态；无查询能力就明确受限，不重新整个组合。
用户停止：取消信号传递给后续可取消步骤；已经发生的写入/费用不伪装撤销。
进程重启：复用现有持久工作/回执恢复；不凭内存Map宣称可靠恢复。

不为所有未来组合预建saga、补偿引擎或exactly-once宣传。只有真实产品已有的有副作用链需要对应回执。

## 5. 所有权表

| 内容 | 唯一负责人 | 其他模块如何使用 |
|---|---|---|
| 正式聊天/修订/发布资格 | est MessageService | 发布/读取窄接口 |
| 模型实际看到的内容 | est请求与window轨迹 | ctx的真实seen视野，不自行推断 |
| 音频/图片资产与引用保护 | est现有MediaService（远端音频按原合同） | 授权asset引用/受控读取 |
| 转写及通话协议 | Siren + est既有映射 | 适配器与voice用例 |
| 声音分析与分析源映射 | oído + est oído接入仓库 | 已授权analysis/audio ref |
| 记忆/I/计划/正式来源 | Mariposa | 现有HTTP公共能力 |
| 浮现作业与当前回合交付 | est SurfacingService | 生命周期/上下文接口 |
| 预约与后台运行/费用 | est现有task/scheduler/ledger | wake工具、HTTP、统一执行入口 |
| 未来情绪状态 | 未来模块（本次不创建） | 明确公共读写合同，不反写记忆事实 |

相互协作的流程属于application层，不属于上表任一个远端内部实现。
