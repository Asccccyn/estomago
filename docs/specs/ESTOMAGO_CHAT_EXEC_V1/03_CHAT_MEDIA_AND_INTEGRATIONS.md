## 1. 本章必须实现的结果

1. 乔生能在同一个聊天界面发送图片、表情包和语音消息；文字与附件组成一条有稳定身份的消息，刷新、换窗及重启后仍能读取。
2. 周家明收到图片时，所选模型确实得到图片输入；界面显示一张图、文字中出现网址，均不能冒充“模型已经看图”。
3. 周家明能通过工具发送已经有权访问的图片或语音。外部图片可以持久导入后发送；已有图片使用 `asset_id`，不让模型重新抄写图片字节。
4. 基础聊天媒体由 est 的媒体服务统一管理，内容后端只持有引用。删除一条相册、帖子或作品记录不会删除聊天原文、记忆桶或仍受聊天证据引用的媒体文件。
5. 保留 Mariposa 现有 HTTP 接入。oído、扎西德勒按 MCP 预留并逐项接线；Siren、Antinomy、许愿星及 X / 小红书保持各自业务归属。
6. 同一前端可以使用多个后端。此次不新增大型插件平台，不为每项功能另开一个 est 子服务，不把外部系统的业务数据复制成另一套可独立编辑的正本。

本章不要求真实付费验收。离线证据证明本地实现；没有真实外部合同或没有联调条件时，逐项报告 `blocked` / `unknown`，不能用 fake transport 的成功代替外部服务已通。

## 3. 统一语义：文件、消息、相册条目分别是什么

### 3.1 三种身份不能互换

- **`asset_id`**：一份已由 est 管理、可重新取得的不可变媒体内容。不是临时下载网址，也不是用户设备文件路径。
- **消息附件引用**：某条消息的某个 revision 使用了哪个 `asset_id`，以图片、表情包还是语音显示，以及排列顺序。它是消息证据的一部分。
- **内容引用**：某个相册条目、私人帖子或纪念作品使用哪个 `asset_id`。内容后端持有自己的业务正文与 est 返回的引用回执。

同一张图片可以被聊天与相册共同引用。只增加关联，不为了每次引用复制文件。文件去重可以按 hash 实现，但不得把“文件内容一样”误当成“消息、相册条目或来源一样”。

### 3.2 本期不扩大 `MessageKind`

沿用数据库现有 `text / sticker / voice / system`，不增加 `image`、`multimodal` 或新的 Mariposa `published_kind`。

| 消息形态 | 本地 kind | 附件 |
|---|---|---|
| 普通文字 | `text` | 空 |
| 一张或多张图片，附带可选文字 | `text` | `presentation:image` |
| 表情消息 | `sticker` | `presentation:sticker` |
| 语音消息，附带可选文字 | `voice` | `presentation:voice` |
| 系统消息 | `system` | 只由宿主产生，不由用户/模型任填 |

`text` 在此是兼容历史的“普通聊天消息”种类；是否包含图片，以附件 DTO 为准。不得因 `kind=text` 就在渲染、模型输入或归档阶段丢弃图片。第一版不支持同一条消息混合语音与其他附件；直接给出清晰的可修正错误，避免设计尚未需要的组合类型体系。

### 3.3 正文与派生文字

`content` 保持原有含义：用户输入或助手正式发出的文字，仍只规范化换行，不 trim、不拆分。图片说明、表情含义与语音转写不能悄悄改写成用户亲自输入的文字。

- 图片说明、表情使用含义是可选元数据，没有填写不阻止图片发送。
- 语音转写明确标记为派生文字，保留原音频及转写来源。
- 已发消息中的正文、附件顺序、派生文字一旦作为某 revision 使用，必须固定。更正转写或改附件需要形成新 revision；不得原地替换已经进入模型上下文的内容。
- 一期可只支持文字编辑、保留原附件；不必同时开放编辑已发附件的页面。文字编辑仍须将同一套附件绑定复制到新 revision。

## 4. 最小数据结构与文件保存

在 est 现有数据库添加下列三张表，表名统一为 `media_assets`、`message_attachments`、`asset_external_refs`。HTTP 路径中的 `assets` 是资源名，不另建一张叫 `assets` 的重复表；Mariposa 的 `IngestMessage.assets` 仍是其既有字段名。不要再为同一引用维护另一套容易漂移的手填引用计数。

### 4.1 `media_assets`

| 字段 | 要求 |
|---|---|
| `id` | 稳定 `asset_id`，由宿主生成 |
| `creation_operation_id` | 创建/导入的幂等键；成功操作不能重复建图或再次付费生成 |
| `state` | 最少区分 `pending/available/failed/missing`；`available` 必须已完成实际文件校验与保存 |
| `mime_type`、`byte_size`、`content_sha256` | 基于实际文件字节，不只信请求头或扩展名 |
| `storage_key` | 受管理目录中的不透明键；不接受用户/模型传入任意绝对路径 |
| `width/height/duration_ms` | 对应类型可填写；未知保持 null，不编数字 |
| `origin` | `upload/import/generated/service` 之一，用于说明来源 |
| `origin_service`、`origin_ref` | 可选外部来源 ID；机密网址和访问 token 不进普通日志或模型结果 |
| `created_by`、`created_at` | 由宿主会话映射实际作者；不能相信模型自填身份 |
| `ingest_purpose` | 已校验的上传用途，例如聊天图片/贴纸/语音或纪念图标/作品；用途决定可接收格式，不是用户自报的额外权限 |

资产 ID 只在取得内容后供发送。`pending` 可向前端用于上传进度，但不得作为可见消息的成功附件。临时文件写入完成后校验并原子提交；失败清理本次临时文件，不删除其他已保存资产。

必要的缩略图、浏览器播放版本属于原资产的派生文件；保留原件与固定的派生版本。不要在每次打开历史时重新压缩，使相同 `asset_id` 返回不同图像。

### 4.2 `message_attachments`

唯一键为 `(message_id, revision, position)`；至少含 `asset_id`、`presentation`、可选说明及固定的派生文字/来源。

必须能查询任何历史 revision 的附件。消息修订不能覆盖旧绑定；旧修订引用也计入禁止物理删除的判断。已有正文 `content_hash` 算法保持不变，避免破坏 Mariposa 原文引用与人工历史选择合同。

另增本地 `attachments_hash` 或 `message_fingerprint`，覆盖规范化正文及有序附件引用，用于发送幂等、修订一致性与轨迹校验。**不要把附件 JSON 拼进旧 `content_hash`，然后假定 Mariposa 已经接受新的 hash 语义。**

### 4.3 `asset_external_refs`

由 est 管理内容后端的引用；至少含 `asset_id`、`owner_service`、`owner_type`、`owner_id`、可选 `owner_revision`、稳定引用 ID、引用自身递增的 `revision`、操作 ID、创建/解除时间。引用状态区分 `protected/committed/released`：protected 是写入进行中的保护 pin，committed 是已确认内容对象引用，released 不再保护文件。唯一键必须阻止同一调用重复加引用。

pending 操作的 pin 也使用这张表，不再新增另一套 pin 计数。确认 content 提交后，在 est 本地事务中把保护绑定到正式对象；失败或回查确认未提交时才解除该操作的 pin。`owner_revision` 是内容对象版本，引用自身 `revision` 用于其 HTTP 更新/解除的并发校验，二者不得混用。

允许的 `owner_service/owner_type` 由服务配置决定，例如内容后端的相册条目、帖子、作品。前端或模型不能伪造“某条聊天已经不再引用这个文件”。

有效引用由 est 同一媒体服务统一查询：

1. 所有历史 `message_attachments` 中的引用；
2. `asset_external_refs` 中 `protected/committed` 的引用，包括结果未知、正在恢复的操作保护。

本期不要求自动 GC。没有实现真实的跨服务引用协调前，宁可保留未挂接文件，也不能按“今天没被相册查到”删除。若提供孤立文件清理，只处理已经证明无引用且无正在提交操作的文件，采用同一事务/锁完成检查与领取；不能检查完无引用后让另一请求插入引用，再继续删除。

## 5. 新增 HTTP API 与前端行为

路径统一 `/api/v1`，认证复用现有会话。写请求使用 `POST/PUT/DELETE`，不要增加当前 Origin 检查未覆盖的 `PATCH`。媒体二进制上传不能挤进现有 5 MiB 的 `readJson()`。

新增和改造的状态写入 HTTP 请求统一使用 `Idempotency-Key` 请求头；更新和删除还必须带 `If-Match: "<revision>"`。GET 返回可更新资源时提供对应 `revision` 与 ETag。更新/删除的 revision 或幂等键不再从查询参数、DELETE body 或另一套 JSON 字段任选读取。模型工具若使用 `expected_revision/idempotency_key`，由宿主适配成这两个请求头；模型不能伪造身份头。

执行顺序为：认证及操作授权 → 查该 actor/操作/目标范围内的幂等回执 → 同键不同指纹报冲突 → 同键同指纹返回原回执 → 只有尚无回执的新操作才检查 If-Match 并写入。这样首次删除成功而响应丢失后，带旧 If-Match 的合法重放仍返回首次成功；不能因对象版本已增加而误报失败。回执查找不得让当前无权用户读取他人的旧结果。更新/删除的幂等指纹包括其原 expected revision。

### 5.1 资产 API

| 新增 API | 输入与成功结果 | 边界 |
|---|---|---|
| `POST /api/v1/assets` | 单文件流或受限 multipart，带 `purpose`；`Idempotency-Key` 请求头；成功返回 `asset_id/mime_type/byte_size/state=available` | 流式限制大小，避免一次性把大文件读入内存；失败不生成假成功 ID |
| `POST /api/v1/assets/import` | `{source_url}`；幂等键在 `Idempotency-Key` 请求头；返回持久保存后的资产 | 仅支持允许的外部图片 URL；适用第 7 节。受信服务私有资源经各自适配器导入，不由模型任意指定内网地址 |
| `GET /api/v1/assets/:id` | 返回已授权资产元数据与相对播放/查看地址 | 不返回存储绝对路径、源站凭据或长期 bearer token |
| `GET /api/v1/assets/:id/content` | 返回文件；语音支持实现所需的 Range 行为 | 仍需认证；响应 MIME 与实际校验一致；过期临时源地址不应影响已导入内容 |

浏览器上传与持久导入各有大小、时间与支持格式的配置上限；在配置样例中写清工程默认值。不要因为一个文件以 `.jpg` 结尾就接受它。同一个资产服务按用途执行两套小的格式白名单：

- 聊天附件用途：`chat_image/chat_sticker/chat_voice`，只接已经实现校验、显示/播放与模型投影的常用位图及音频。
- 纪念用途：`creation_icon/creation_work`，除已支持位图外，可接经核实并限制大小的 SVG、单文件 HTML 和可播放短视频。SVG 限图标或作品；HTML 限作品；视频只接受实际接通的 MIME/解码格式。纪念用途通过校验不代表这种文件可以直接送入聊天或模型视觉接口。

文件仍统一经 `POST /api/v1/assets` 保存，不增加作品文件服务器。可执行内容按 06 的隔离预览规则展示，不在 est/content 进程里执行或构建。HTML/SVG 内容读取响应自身也要采用适用的 CSP sandbox、禁止同源权限并设置 `nosniff` 等必要头；不能只靠某一个页面上的 iframe sandbox，以免资产 URL 被直接打开后在 est 主站来源执行。未实现安全预览的 active MIME 只允许下载且明确未支持预览，不能按普通图片直出。

首版可以用 Node 内建文件/HTTP 能力与一个必要的流式 multipart 库。需要新增库时说明用途并锁定版本，不能为此引入整个媒体管理平台。

### 5.2 消息 API 扩展

保留原发送入口：

```json
{
  "client_message_id": "client-generated-id",
  "content": "这张照片给你看",
  "occurred_at": "2026-10-11T09:00:00+08:00",
  "attachments": [
    {"asset_id": "asset_existing_id", "presentation": "image"}
  ]
}
```

约束：

- `content` 仍必须是字符串，可以是空字符串，但只有至少一个有效且可访问的附件时才允许空正文发送。
- 不接受附件中的任意 URL、磁盘路径或 Base64。发送前先经过资产创建/导入。
- kind 由宿主按附件组合与用途校验/确定；兼容旧请求，但不任由前端声明一个不一致的 `kind`。
- 先校验全部附件存在、已完成、属于本授权范围、格式匹配；全部通过后，消息、revision、附件绑定、outbox、turn、attempt 同事务提交。
- 同一 `client_message_id` + 同一完整请求指纹返回原结果；同一个键却改了正文/附件/顺序，返回 `IDEMPOTENCY_CONFLICT`，不能无声返回另一条请求的成功。
- `client_message_id` 保留为消息身份/既有幂等兼容字段；旧纯文字POST只带此字段仍有效。新前端可同时传 `Idempotency-Key`，两者必须一致，不允许不同值各自命中不同操作。媒体导入与内容操作不再复用 `client_message_id` 字段。
- `GET .../messages` 在每个 message 的当前 revision 返回附件 DTO。历史/指定 revision 的内部读取也从同一绑定表取，不以当前附件冒充旧版本。
- `PUT .../messages/:id` 请求体仍可只提交修改后的文字，默认沿用原附件；使用 `If-Match` 校验所编辑的 revision，`Idempotency-Key` 保证重试不再次修订。旧附件引用不被删除。没有实现附件编辑时，不接受未定义的新附件修改字段。这里新增必要的并发前置条件，必须同批更新前端；尚未刷新的旧页面缺条件时返回428并提示刷新后重新编辑，不能自动套用最新revision覆盖别人修改。交付报告明确这一兼容变化。

保留 `owner/assistant/system` 等现有消息 speaker。内部作者 `qiaosheng/jiaming` 与消息 speaker 的映射由宿主完成，不做全局更名。`media_assets.created_by` 记录来源作者，不等于仅该作者能使用；双方在同一私密空间内可引用对方已经共享的合法资产，权限由宿主的实际共享范围判断。

### 5.3 前端

继续使用原生 HTML/JS/CSS；不为了上传按钮改为新的前端框架。

- 输入框旁新增附件选择与预览；图片、语音各自显示上传或转写状态。
- 上传失败保留文字与未发送附件；点击重试复用操作 ID。发送成功只清理属于该次发送的草稿，保持现有 `draftGuard` 防覆盖规则。
- Enter 只换行，独立发送按钮触发发送；IME 合成期不发送。
- 文本继续安全地作为文本显示；附件使用明确的 `img/audio` 元素，不把模型输出字符串直接交给 `innerHTML`。
- 关闭页面后重新进入，从数据库返回的附件重建气泡，不依赖此前的浏览器 Blob URL。
- 图片无法取得显示“附件暂不可用”和错误状态；不能用占位文字代替图片后又显示“全部正常”。
- 语音保留原音频播放与标明来源的转写显示；转写不是说话者亲手输入的文本。
- 表情包先支持选择/发送已有资产及可选含义。完整表情包库、自然语言搜图、向量模型不属于完成基础发送的前置条件。

## 6. 真正的看图与模型媒体工具

### 6.1 统一媒体输入投影

新增一个有限职责的投影器，例如 `apps/host/src/media/model-input.ts`。它接收稳定消息 revision + 附件，输出所用驱动认可的输入，不自行决定换窗、删历史或生成摘要。

必须覆盖全部入口：

1. 本轮用户消息；
2. 同窗历史追赶；
3. 人工选择带入新窗的历史；
4. 失败重试与进程重启后的轨迹恢复；
5. 主模型按需读取旧消息/图片的路径。

特别修复 `manual-selection.ts:148` 的类型过滤，以及 `loadContents():304–313` 的纯文字读取。语音/贴纸是真实聊天消息，不能只在前端勾得上、后端却拒绝。选集仍按已确认 revision 固定附件身份；空正文图片消息不能被当成“零成本空记录”。估算包括图片/音频的模型输入成本，依据所选模型已核实的计量方式；没有精确计量时标注粗估并保守控制容量，不把 Base64 字符数直接当 token 数，不伪造精确值。

估计统一调用 05 指定的 `apps/host/src/usage/estimator.ts`，本章不再写另一套字符/图片估算法。纯本地预览读取已保存元数据和固定投影版本，不触发下载、转写、生成或外部计数。语音只将转写送给主模型时，转写文字计入实际计划输入；未发送的原音频不再额外计作主模型音频 token，Siren 转写费用另记服务用量。

模型实际收到的媒体资产/投影版本应加入已见证据。只返回资产元数据、不传视觉块时，不能把整张图记成“已看见”。图片 OCR、语音转写与原始文字的来源区分保留，不能自动把派生识别结果认证为逐字原话。

模型请求使用经确认支持图片的确切型号。所选驱动或型号尚未支持图片时，消息和图片仍保存，但本轮回复明确阻断为 `MODEL_VISION_UNAVAILABLE`，不偷偷将图片丢掉继续回答，不静默切换模型。

Provider 的图片字节/URL 格式按真实接口实现。给模型传私有站点的 cookie URL 通常不能让 Provider 取图；实现时选用 Provider 支持的二进制/数据块或可访问资源形式。若生成一次性可访问 URL，应由服务端生成、最小范围使用，不把用户的整个会话凭据放在 URL 上。

### 6.2 与缓存和历史的约束

资产文件不可变，派生版本固定。同一消息进入同一窗口时应得到稳定投影，不能每次请求重做 OCR、重转码或重新签出一个不同字面值的 URL，导致前缀在没有用户修改时变化。

具体传输和缓存相容性必须由缓存章节共同验收：

- 保存稳定资产引用及投影版本，发送时确定性物化；不在数据库、普通日志或事件中复制大型 Base64。当前 `window-trajectory.ts` 会直接保存消息 JSON，必须与 `supervisor`、runner 的装配边界一起调整，不能只在发送函数临时插图而失去可恢复轨迹。
- 轨迹持久化形态与供应商 wire payload 明确区分：内部 `asset_ref` 不直接传给 Provider；实际发送时从不可变文件和已固定转换版本物化，记录可重算的完整输入投影 hash。新旧请求在同一语义/物化规则下执行前缀断言；不能拿未含图的旧文字对象与新多模态对象比较后忽略失败。
- 如果物化方法会改变已发出的历史字段，不能绕过现有 append-only 断言。调整为稳定的传输形式，或走已批准的窗口处理流程。
- 动态工具目录和模型能力更新也不能在同一窗口偷偷改写已冻结的工具前缀。
- 老图退出当前输入不等于删除图片或原文。需要再次查看时明确重新装载；不能把长期存储与模型当前视野合并成同一开关。

### 6.3 主模型工具

工具名称采用本包统一名称；进入现有工具校验/执行层，不开放任意 filesystem、任意 shell 或动态代码执行。

| 新增工具 | 最小参数 | 行为与结果 |
|---|---|---|
| `media_import` | `source_url`；宿主派生操作 ID | 后端取得图片字节并持久保存，返回 `asset_id`、实际类型和大小；链接只是导入来源 |
| `chat_send_attachment` | `asset_id`、`presentation`、可选 `content` | 以周家明当前房间身份正式发布附件消息，持久化成功后才回成功；对当前工具调用幂等 |
| `creation_save_artifact` | `format:svg\|html`、`content`、`client_operation_id` | 将周家明写好的图标/单文件小作品持久保存，返回 `asset_id`；不执行作品代码，不发布纪念记录 |

读取旧图片若需要新增工具，可使用 `media_read`，参数仅 `asset_id`，且必须与 `conversation_read` 返回的授权资产引用相接。结果通过驱动支持的视觉输入送给模型；回一条文件地址或图片描述不算模型取得原图。若无需独立工具即可在原文回读中返回视觉块，则复用原入口，不新增同义入口。

`chat_send_attachment` 的消息发布应复用 `MessageService` 和现有发布事件/outbox，不能另写 SQL 绕过消息事实链。工具已经发布的图片不能再被普通文本分段发布逻辑重复发送。文字先发、工具发图、文字续答的顺序应按实际发布序列保存，不能把先后关系重排成全在回合末尾。

幂等键由 `turn_id + tool_call_id + 规范化参数指纹` 等稳定上下文派生，不能由模型任意指定别人已有的操作。未知结果需要查询原操作结果；不得因为超时就再次收费生成或再次发图。

`creation_save_artifact` 是受限的文件保存入口，不是编程执行工具。`format=svg` 固定对应 `image/svg+xml`，`format=html` 固定对应 `text/html`；用途限定纪念图标/作品。`content` 按配置限制大小并走同一媒体校验/保存服务；不接磁盘路径、任意 HTTP 请求、依赖安装或 shell 指令。宿主将 `client_operation_id` 作用域绑定到真实 actor 和本工具，作为可恢复的创建幂等键；同键不同内容直接冲突。它与 HTTP 上传共用保存逻辑，需要经过 HTTP 适配时映射到 `Idempotency-Key`，不新增同义保存后端。取得 `asset_id` 后再调用 06 的作品创建/更新工具，模型仍有权只保存图标或暂不发布纪念记录。

### 6.4 “周家明单独上传”的准确含义

| 图片来源 | 可行路径 |
|---|---|
| 乔生已经上传的图片 | 主模型获得合法 `asset_id`，直接发送或交内容后端创建重要相册引用 |
| 生成服务已产出的图片 | 适配器接收实际文件/资源引用，导入资产后返回 `asset_id`；模型不必读写图片字节 |
| 浏览工具找到的可访问图片 | `media_import` 持久导入，再发送/建立内容引用 |
| 用户手机或电脑里尚未分享的图片 | 用户上传，或已有明确授权的本地服务提供受控资源；est 不凭空获得设备相册读取权 |

“保存到重要相册”属于内容后端的条目创建，不是再次上传。同一张图只传 `asset_id` 和必要说明。只有获得资产和内容记录的真实回执后，周家明才能宣称保存完成。

## 7. URL 导入与文件读取的简洁安全边界

这是防止把“导一张图”变成任意内网请求或文件读取的必要实现，不是要求用户每张图走审批。

1. 普通 URL 导入只接受 `https`；如确有已知服务必须使用其他协议，使用专用适配器，不开放任意协议。
2. 拒绝带用户名/密码的 URL、`file:`、localhost、环回/私网/链路本地/云元数据地址等非公开目的地。DNS 解析与实际连接目标必须一致，并对每次跳转重新检查；设置有限跳转次数，不能只检查最初字符串。
3. 不能用“域名最初解析为公网”通过检查后再由独立 fetch 重新解析访问内网。选用能控制连接目标的 HTTP 实现，或可靠的已配置出站代理；无法实现时禁止任意 URL 导入，先保留已知生成/浏览服务适配器的导入。
4. 不转发浏览器 Cookie、est 登录 token、外部站点账户凭据至图片 URL。需要登录的小红书/X 资源由其已有连接器获取，再通过受控资源引用导入。
5. 实际响应流限制字节数、总时长与下载并发；检查实际 MIME/文件头，处理图像解码尺寸，拒绝 HTML 错误页冒充图片。
6. 用户本机同主机服务（Siren、oído 等）是**已配置的可信服务入口**：由静态配置指定基地址，适配器接受该服务的资源 ID 或受约束相对路径；模型不能把它当成任意内网 URL 代理。
7. 错误日志只记录稳定错误码、操作 ID、服务 ID及必要计数，不记录带 token 的 URL、图片内容、转写或私人正文。

测试应覆盖重定向到内网、DNS 目标变化、超大响应、非图片响应、取消下载、临时链接失效，以及重复导入请求。无需访问真实外网，可用受控本地 transport fixture 验证策略分支。

## 8. 语音与生成服务

### 8.1 Siren 继续负责语音业务

est 负责录音/发送/播放的聊天交互、消息绑定、调用结果与用量，Siren 继续负责识别、合成及其既有语音业务。不要把 Siren 的内部代码复制入 est。

实施前读取实际 Siren 当前版本并记录：

- 转写输入、返回格式和异步状态；
- 合成接口是否只返回音频字节；
- 是否已有保存与消息关联的完整业务入口；
- 重复请求处理、下载/播放方式、取消、超时；
- 实时通话入口的 WebSocket/流媒体合同。

只有合成接口并不等于历史语音可播放。若当前可复用的完整保存业务只暴露 MCP，先按真实合同调用它；如果要增薄 HTTP 入口，列入跨仓接线项，不能在 est 中捏造一个对方不存在的路由。

**用户语音流程：**浏览器录音 → 上传并保存原音频 → Siren 转写 → 发布/处理带来源标记的语音消息 → 主模型输入转写或确实支持的音频块。第一版允许先完成转写再启动模型回合；转写失败保留已上传原音频及草稿状态，显示重试/取消选择，不发布一条伪转写文字。

若选择先持久化聊天消息再异步转写，必须补齐待转写状态与回合门：转写未完成不能空输入调用模型，转写完成不得原地改已发出的 revision。两种实现只能选一种并贯穿 UI、消息事务和测试，不能半段采用一种、半段采用另一种。

**助手语音流程：**模型调用实际语音工具 → Siren 取得完整结果 → est 取得或登记可持久重取的音频资产 → `chat_send_attachment`/共享发布业务发送语音消息。外部结果已生成而本地保存结果不明时，查询原操作；不得自动再生成一遍。

Siren 若已永久保存音频，可由适配器按稳定服务资源 ID 取得字节并完成 est 资产登记，避免业务正文双写。若选择只保留远端资产引用，必须明确验证长期重取与服务离线行为；不能以随时过期的临时播放 URL 充当 est 的持久文件。本章默认优先将聊天附件字节保存进 est 媒体目录，源服务仍保留它自己的业务记录。

### 8.2 表情包

一期仅要求：位图/GIF 等实际支持格式导入、已有资产选择、可选使用含义、图片显示与发送。动态格式不受模型支持时，保留原件用于前端播放，给模型传明确标注的固定视觉派生版本；不能假装它看过整个动画。

表情的含义属于用户/周家明定义的说明，不从像素强制推导情绪。完整检索、向量库与批量分类在内容功能阶段实施。

### 8.3 图片生成

生成模型是外部服务；只有生成接口和计费合同已经核实才注册对应工具。未配置时返回 `GENERATION_PROVIDER_UNCONFIGURED`。本章不写死未经核验的供应商 URL、型号或参数。

生成适配器归一化三类结果：实际图片字节、可下载资源引用、待完成任务 ID。前两者保存为 est 资产；任务型结果轮询/回查有总时限和次数上限，复用原任务 ID，不重开计费任务。

最终返回模型的结果保持小：资产 ID、实际格式/尺寸、来源操作 ID、完成状态；大段 Base64 在服务之间处理。要进入聊天再走正式消息发布；要进入重要相册或纪念作品，交内容服务建立引用，不因“生成成功”自动新建桶或相册条目。

### 9.2 最小注册结构

在 `apps/host/src/integrations/` 内增加静态注册与小型适配器即可。每个条目写明：

- 服务 ID 与 `http/mcp`；
- 基地址或明确的受支持传输配置；
- 凭据引用名，值仅在服务端读取；
- 允许的工具与经过核实的输入/输出合同；
- 超时、取消、重试分类、是否会产生外部写入或付费；
- 当前状态：未配置、合同待核、可用、故障。

不要把远端返回的 JavaScript、shell 字符串或任意 JSON 对象当成可执行插件。不得使用 `eval`、`new Function` 或动态 shell 拼接来执行工具。不要提供一个模型可任填 URL、HTTP method、headers 的“万能调用器”。

### 9.3 MCP 必须真的建立传输

接 MCP 的最小完成条件：

1. 使用所选、锁定版本的 MCP 客户端实现支持的真实传输；完成初始化及生命周期处理。
2. 读取并核对 `tools/list`，只装配已配置的能力，记录工具 schema/合同版本；不因远端增加工具就自动扩大权限。
3. `tools/call` 的实际参数、结果、错误、超时和取消均经过适配。
4. 将 MCP 文字、图片、资源链接等结果转换为当前模型驱动支持的内容。图片字节通过媒体服务取得资产；不能把 image block 的 Base64 原样塞成普通正文。
5. 断线/重连不能重复执行结果未知的写操作。区分确定未执行、已执行、结果未知；对能查询状态的操作查询原回执。
6. 实际工具装入当前驱动的工具列表并能在模型工具循环中执行。只在配置文件加 URL、只做一个列表页面，都不算完成。

现有 SDK `build-options.ts` 会明确阻断非空 MCP allowlist；要支持 SDK 路径，必须按其锁定版本真正实现 `mcpServers` 映射并更新运行门，不能仅删除这个阻断条件。OR 路径不经过 SDK，应由 est 的 MCP 客户端处理调用，再以 OR 支持的工具结果回传。

第一批可以优先完成当前默认的 OR 路径，其他驱动如尚未接线就列出对应 `blocked`，不得把一条驱动通过写成所有驱动通过。不要为提供客户端能力额外建立一个 est 公网 MCP 服务器，除非另有明确需求。

### 9.4 同一前端

前端通过 est 已认证的薄代理或内容章节约定入口取数据；服务凭据不下发到浏览器。可以先做导航和结果卡片，按需接已有页面，避免为了“同一前端”一次重写所有外部 UI。

浏览器能打开外部页面、后台能列出工具、主模型真正能调用，是三项独立证据。状态面板分开显示，不合并成一个自填绿色状态。

## 10. 原文归档与引用删除

### 10.1 Mariposa 附件合同待核

本基准 est 的 `IngestMessage.assets` 类型是 `string[]`，实际始终发送空数组；这只能证明 est 本地类型，**不能证明当前 Mariposa 已接受任意 `asset_id`、可重取图片或新增资产对象**。

开始改归档前，应对当前 Mariposa 的输入 schema、服务实现和 fixture 核实：

- `assets` 每项是什么：稳定 ID、URI，还是其他已定义引用；
- 可识别的命名空间、来源实例及访问方式；
- 是否参与完整性 hash、幂等指纹与回执；
- 重放、正文修订及附件变化的语义；
- 纯语音、贴纸、图文消息允许的 `published_kind`。

保持已有映射 `text→chat_message`、`sticker→sticker_message`、`voice→voice_message`。未经确认不发送新的 `published_kind` 或新的 assets 对象结构。

可以提出供联合审计的最小内部资产引用结构，例如：

```ts
// 拟议接缝，不是 Mariposa 已支持的输入 schema。
type SourceAssetDTO = {
  origin_instance: 'estomago';
  asset_id: string;
  mime_type: string;
  content_sha256: string;
};
```

如果实际 M 只接受 `string[]`，按真实合同把稳定引用编码为它接受的字符串；不把上述对象强塞进去。Mariposa 存原文证据与媒体关联，不承担相册条目、帖子正文或作品管理。

未核实或未落地时，含附件消息的媒体归档状态标为 `ASSET_ARCHIVE_CONTRACT_UNVERIFIED` / `blocked`，保留本地完整消息、附件和待处理 outbox。纯文字现有归档继续运行。不能把含附件消息的 `assets:[]` 发送成功后显示“此消息连附件已全部归档”。若实现分别确认正文和媒体，必须有明确的独立状态与回执；不能沿用一个“已归档”字段制造完整成功。

归档失败不撤销本地聊天保存，也不自动删除文件。缺少源端 ACK 时，依赖该来源的 hold 按原有来源就绪规则报真实状态，不能伪造来源收据。

### 10.2 内容后端引用合同

引用协调以 06 的 est 先保护、content 提交、est 确认流程为准。est 的 content adapter 直接调用同进程媒体服务；不在一次 est 请求的同步链里让 content 回调 est。保留以下受控服务接口作为同一业务方法的协议映射，不向普通浏览器或模型开放任意引用管理：

- `POST /api/v1/assets/:id/references`：登记一个已允许的内容域引用，使用 `Idempotency-Key`，返回 `reference_id/revision/state` 与 ETag；幂等。
- `DELETE /api/v1/assets/:id/references/:referenceId`：解除本服务有权管理的引用，使用 `Idempotency-Key` 和引用自身的 `If-Match`；返回解除回执及递增 revision；幂等。

调用方身份由宿主配置明确映射，不接受浏览器自报 `owner_service` 作为授权依据。content 不使用这些接口在同步请求中向 est 回调；本期调用者是 est adapter 及其受控恢复流程。引用操作与其他写入遵循第 5 节的授权后先查合法幂等回执、再检查 revision 的顺序。

跨服务最小可靠流程：est 认证并校验资产 → 持久记录操作意图、在 `asset_external_refs` 先建立 protected pin → 带可信 actor/幂等键请求 content 提交正文和资产 ID 集合 → est 按真实回执在本地事务确认正式引用，再解除已被替换的旧引用/多余 pin。结果未知时保留保护，通过原幂等键回查恢复；不得先解除旧图再等待新内容提交。没有 content 同步反调 est、没有另一张 content 引用账本。删除内容记录只解除相应引用。进程崩溃时留下待恢复记录或多余引用可以核对收敛，不能为了立即清理而误删仍被使用的文件。

### 10.3 删除规则

1. 删除相册条目/私人帖子/作品 = 删除或隐藏该业务记录并解除其外部引用。
2. 不删除相关桶、“我们的话”、聊天正文或原文收据。
3. 任何历史消息 revision 仍引用的媒体，不允许物理删除。
4. 内容后端无文件系统/GC 权限；不得直接调用媒体目录删除或自行判断无人引用。
5. 本期没有“彻底销毁聊天证据媒体”的需求，勿新增这样的普通按钮。若未来有单独明确需求，再定义引用失效和证据保留方式。

以上删除相册条目的动作无需逐条申请审批；引用检查由程序自动执行。

## 11. 错误与观测

沿用 HTTP `{error:{code,message}}` 与工具 `ToolExecResult`，工具失败通过 `output.error_code` 返回。可补 `retryable`、`outcome_unknown`、`operation_id`，不要另造一套不兼容的大型错误框架。

| 稳定错误码 | 条件 | 必须结果 |
|---|---|---|
| `ASSET_NOT_FOUND` | 引用不存在或不可见 | 拒绝发送；不暴露其他授权域资产存在性 |
| `ASSET_NOT_READY` | 上传/导入未完成 | 保留草稿；不创建半条正式消息 |
| `ASSET_TOO_LARGE` | 实际流超过上限 | 停止读取，清理本次临时文件 |
| `ASSET_TYPE_UNSUPPORTED` | 文件类型/解码格式不支持 | 明确拒绝；不按扩展名冒充图片 |
| `ASSET_SOURCE_NOT_ALLOWED` | URL/跳转/目标不符合边界 | 不访问该目的地 |
| `ASSET_IMPORT_FAILED` | 导入确定失败 | 可重试时复用操作 ID；不假称已存 |
| `ASSET_STORAGE_UNAVAILABLE` | 文件不可写或历史文件缺失 | 保存失败如实反馈；已有正文仍可读 |
| `IDEMPOTENCY_CONFLICT` | 同键不同请求指纹 | HTTP 409；不默默复用另一结果 |
| `MODEL_VISION_UNAVAILABLE` | 当前驱动/型号未实现看图 | 本地消息保存；回复明确 blocked，无静默降级 |
| `MEDIA_TRANSCRIPTION_FAILED` | 语音转写失败 | 保留音频与草稿/待处理状态，不空输入唤起模型 |
| `INTEGRATION_UNCONFIGURED` | 未配置服务 | 不连接、不重试到默认地址 |
| `INTEGRATION_CONTRACT_UNVERIFIED` | 合同尚未核实 | 能力 blocked；不以 fake 冒充 |
| `INTEGRATION_TIMEOUT` | 外部调用超时 | 写操作区分结果未知；不无条件重复 |
| `ASSET_ARCHIVE_CONTRACT_UNVERIFIED` | M 媒体合同未确认 | 本地保留、媒体归档 blocked |
| `ASSET_REFERENCED` | 清理对象仍被引用 | 拒绝物理删除，不解除聊天引用 |

把错误码、操作/消息/资产 ID、状态与必要计数写入既有事件和记录面板。消息正文、转写、图片 Base64、源站完整私密 URL 和凭据不得进日志。本包告警章节规定统一观测时，以该章路由规则接出，不在此再建另一套告警服务。

## 12. 分批实施与验收

### 批次 M1：本地资产与聊天附件

实现数据库迁移、媒体服务、上传/读取 API、DTO、发送事务、前端附件与历史渲染。

必须有意义的用例：

1. 旧文字消息不迁移内容、不改变 hash，原有发送/编辑/历史仍工作。
2. 空文字 + 有效图片可发；空文字 + 无附件仍拒绝；失效附件与非法混合组合不会形成消息/outbox/turn 半套状态。
3. 一条多行文字加两张图片，顺序、正文和附件在刷新/重启后保持；Enter 不触发发送。
4. 同一次点击重试只有一条消息；换附件但复用原键返回冲突。
5. 编辑正文后新旧 revision 均能读到正确附件；旧媒体不被删除。
6. 非法路径、超大流、错误 MIME、磁盘写失败各有可断言错误；无私人内容日志。

### 批次 M2：模型输入与媒体工具

实现统一投影器、当前驱动看图、`media_import` 与 `chat_send_attachment`，接入工具副作用回执。

必须有意义的用例：

1. 捕获实际提交给驱动的 payload，确认存在正确视觉块及对应图片内容，不能只断言工具函数被调用。
2. 新窗手选历史、同窗追赶、重试、重启均恢复相同附件；没有自动丢图或自动摘要。
3. 不支持视觉的型号保存消息但不给假回答；未发生静默模型切换。
4. 同一工具调用重复处理只发一张图；“已导入但回执丢失”可找到原资产；结果未知的生成不会自动再收费。
5. URL 导入策略覆盖第 7 节边界；既有 asset 发送不发生无谓重新下载。
6. 图片投影变更不能绕过缓存前缀断言；敏感二进制不进入普通日志。
7. `creation_save_artifact` 保存 SVG/HTML 后可按资产 ID 重开；同键不同代码冲突，同键重试不建第二份；全过程没有宿主执行代码或 shell。普通聊天附件入口仍拒绝不支持的作品类型。

### 批次 M3：语音、表情与外部适配

先逐个确认真实外部合同，再接线。未知服务状态可保留 blocked，但本地实现和可测分支必须完成并如实列出剩余项。

必须有意义的用例：

1. 语音原文件、转写来源、消息气泡、历史播放一致；合成成功/保存失败不能显示发送成功。
2. 表情图片和可选含义可发送；普通文字不会误被当成表情指令。
3. 至少一个受控 MCP fixture 完成初始化、列工具、真实调用、取消、超时与断线恢复；不是静态返回 PASS。
4. OR 的 MCP 工具循环实际执行；SDK 若未接，非空 allowlist 仍明确 blocked，不能移除门后静默丢工具。
5. MCP image/resource 结果被正确保存与传递，模型没有收到大段不可解释的 Base64 正文。
6. 外部服务故障只使相关能力失败，基础文字聊天与本地历史仍能使用。

### 批次 M4：媒体归档与跨域引用

核对 Mariposa 当前 schema 后填充真实资产归档合同；配合内容章完成引用登记/解除。

必须有意义的用例：

1. 实际合同不支持附件时显示 blocked，不把 `assets:[]` 记成完整附件归档成功。
2. 合同支持后，请求与回执可对照到正确资产 ID/来源；文本 hash 不变；归档重试不重复创建来源。
3. 同一张图片被聊天和相册引用，删除相册后聊天与旧 revision 仍能打开图片；桶与原文不受影响。
4. 内容服务重复登记/解除引用幂等；一次失败不错误减少另一条引用。
5. 在登记引用与清理并发、以及跨服务中断时，不出现已提交记录指向已删文件。
6. 更新/删除首次成功但回执丢失，使用相同幂等键与原 If-Match 重放仍返回原成功；变更请求内容或越权重放均拒绝。引用回执中的 revision 不与内容对象 revision 混用。
7. SVG/HTML 在隔离作品页以及直接打开资产地址两条路径下，都不能取得 est 主站来源权限、读取凭据或执行内容写操作；只验证 iframe 页面不算完整覆盖。

所有测试使用独立临时 `ESTOMAGO_HOME`，按仓库要求前台、分批、串行执行。默认关闭真实供应商调用、真实外部发帖、真实推送与付费生成。测试报告分别写“本地可验证通过”“外部合同已核”“真实联调未执行/blocked”，不能合成一个总 PASS 掩盖未完成接线。

## 13. GLM 完成报告必须包含

- 最终 SHA、修改文件、追加迁移、配置新增项与兼容方式。
- 哪个驱动/模型输入形态已实现，哪个仍 blocked；图片进入实际 payload 的脱敏测试证据。
- 所有新增 API 和模型工具的请求/回执样例；样例只用测试资产，不附私人图片、文本或 token。
- Siren、oído、扎西德勒、Antinomy、Superposition、X/小红书各自的真实合同版本与接线状态；仅有预留配置的明确写“预留”。
- Mariposa `assets`/hash/`published_kind` 的实际核验结果与未解决差异；没有合同不擅自改 M。
- 附件删除与跨域引用用例结果，确认原文、记忆桶、历史修订未因内容删除丢失。
- 已知限制：格式、大小、视觉驱动支持、实时通话是否完成；不得将语音条完成写成实时通话完成。

交付标准是可追溯的媒体事实链：**取得文件 → 保存资产 → 正式消息/内容引用 → 模型实际输入 → 历史重开 → 正确归档状态**。每个环节使用真实回执，不用枚举、配置占位或页面图标替代完成证据。
