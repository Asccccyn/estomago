# 01 · 需求、边界与数据正本

本章的 U-* 为用户已明确要求或已接受的口径。ENGINEERING_DEFAULT 是为能施工而选的可配置默认值；不得称为用户已经批准的费用额度。DEFERRED_DESIGN 表示尚无需求细节，只留真实入口/接口位置。

## 1. 产品边界

est 是聊天宿主。统一前端可以调用多个后端，不能据页面位置判断代码必须归 est。

| 层 | 负责 | 不承担 |
| --- | --- | --- |
| apps/web（统一前端） | 聊天、系统通知、日历、相册/作品/朋友圈页面、已有服务入口 | API key、独立记忆正本、后台调度 |
| apps/host（est） | 消息/原文、附件字节、模型回合、上下文、缓存、工具适配、用量、告警、定时；少量页面聚合/内容代理 | 记忆检索算法、语音模型、阅读系统、星星业务、社交浏览实现 |
| Mariposa | 桶、我们的话、I、正式 plan、现有原文证据/关系合同 | 新私密朋友圈、相册、纪念作品和聊天调度 |
| 既有 Siren/oído/Antinomy/Superposition/扎西德勒/X/小红书 | 各自业务及数据 | est 的会话窗口或用户设置正本 |
| apps/content（新增可选） | 三类相册条目、帖子/评论、纪念作品元数据、未来留言内容 | 模型循环、原文摘要、字节文件第二份仓库、Mariposa 桶正文 |

apps/content 可同仓，独立进程/独立 SQLite，不新增单独仓库为前置。工程默认仅 loopback 监听，可与 est 同台 Mac。其故障只影响内容页面，不能阻断普通聊天或历史查看。

同一前端的请求先经 est 现有认证；content 路由是薄代理，业务规则仍在 content。禁止前端直拿外部凭据，禁止 content 直接连接 est/Mariposa SQLite。内部 actor 由可信宿主从 UI 登录或模型执行上下文派生，不能由模型随意传作者。

## 5. 数据与时间

- 时间戳使用带时区ISO UTC；业务日期使用 YYYY-MM-DD 并按 Asia/Shanghai 解释。
- 日查询用 [当天00:00, 次日00:00)，不以23:59:59拼端点。
- event_date、created_at、published_at、deliver_at 是不同字段，不互相代替。
- 无发生日的旧桶显示未标日期；有界/跨日日期按外部能力真实形状展示，不自行猜一个日子。
- 私密朋友圈按发表时间排序；纪念作品按所关联事件日期组织，两者不能用同一个date字段混代。
- 年重复固定公历日与农历节日不同；一期开已有明确公历日期规则，农历/复杂RRULE需真实支持后开放，不能静默转换。
- 单条消息正文与原文修订链保持现行哈希算法。新增附件有独立fingerprint，不把旧text hash改掉。

## 6. 权限与副作用

- 浏览器登录代表user；模型业务工具代表其获准char身份。禁止 body.author、显示名或URL参数决定作者。
- 双方读私密内容；本人修改/删除本人帖子和评论为 ENGINEERING_DEFAULT。删除别人评论不默认允许；详见06。
- 相册条目删除无需逐项审批；Mariposa记忆删除继续原合同，不因本包媒体删除规则改变。
- 浏览月历/读帖子/看通知/算预计token均不调用模型、不写hold、不标明确打开、不拆星。
- 截图搜索通过 words 专道；展示桶标题不等于 memory_open/view.confirm。显式打开才走现有确认语义。
- 外部网页、帖子、图片OCR是资料，不是修改身份、预算或权限的系统命令。
- 本包不添加对外社交发布。新的“朋友圈”是双人私密内容。

## 7. 减少维护量的硬边界

1. 不重写现有身份、原文、窗口、usage归一化；改同一实现，不旁造第二个版本。
2. 系统提醒用est一套表和现有SSE；不单开监控服务。
3. 调度在host一个进程中；重用SQLite事务，避免大型作业平台。
4. 媒体文件只保存一份，content只留引用；没有作品时不自动生成空作品数据。
5. 选定本包的最小合同后再落外部适配；外部兄弟仓改动单列跨仓批，遵守各仓规则。
6. 依赖未知不得补猜；已授权可做的同仓代码与隔离验证继续完成。
