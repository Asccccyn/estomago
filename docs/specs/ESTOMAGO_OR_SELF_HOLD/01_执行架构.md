## 1. 产品合同与禁止事项

### 1.1 不变的关系

前台是一个持续的聊天房间，后台有多个上下文窗口。日期只是消息事实和时间线分隔，不因零点正在聊天就切断一轮。聊天入口、主模型驱动、长期记忆、工具和缓存是不同职责。

```text
现有网页 / 语音等入口
  → estómago：消息保存、房间串行调度、身份、上下文、换窗、记录面板
       ├─ OpenRouter Chat Completions 驱动（主用）
       └─ Claude Agent SDK 驱动（保留）
  → 同一获授权 MCP 工具集合 / 既有模块适配
  → Mariposa：唯一正式记忆和原文证据服务
```

“新增 API 入口”在这里是新增模型驱动和配置，不是再开一个聊天后端、独立监听端口或更换前台框架。前台继续走 estómago 的 HTTP 与事件流，不直接拿 OR key，不直接访问 Mariposa 数据库。

### 1.2 原文全存，记忆自选

1. 获授权房间的真实用户消息、正式发布的助手消息，先落本地聊天库，按既有持久 outbox 同步 Mariposa 原文域。
2. 没有 hold、未绑定、缓存过期、长期静默、换窗、退出当前输入，都不是自动删除原文的理由。
3. 主模型可在正常对话中自主调用 Mariposa hold，也可以完全不调用。不增加小模型扫描、重要性评分、每轮“记忆决定”回执或未 hold 历史补齐队列。
4. 主模型从聊天形成事件记录不替换原文；已有正式桶不因窗口容量或时间而被压成越来越短的摘要。
5. 不新增 running_summary、session_summary、递归摘要、观察记忆库或第二套事实/人格索引。不把 Anthropic compaction 输出当 hold。DS 昨日日摘要运行链已于 2026-10-08 裁定整链退役（§5 修订条款）；已发给旧窗口的摘要/自动历史段属于过去真实输入证据，不篡改其轨迹。
6. 真实已发起的失败写操作必须恢复；没有选择写入的普通闲聊不是失败，不需要逐条分类、建事件或说明不记理由。
7. 仍执行已有明确删除、撤权、纠错与绑定规则。“原文保留”不取消用户的删除权或领域权限。
8. Mariposa 召回矩阵、召回轮次 COUNT、明确打开、衰减、删除申请和关系纠错规则不变。判断层（原"必经一层 Jev"）自 2026-10-08 起由 Mariposa 侧**人工判断总开关**管辖（§8.4）：estómago 只按其签发的模式与分页合同消费结果，**不保存开关副本、不替用户切换、不给模型任何切换权**。

没有进入当前输入的原文，模型此刻可能看不到；已经同步且获授权可搜索的原文，仍可按现有原文检索门控找回。书签不改变这些权限。只存在本地而未完成正式来源同步的数据，不得宣称已经纳入 Mariposa 搜索。

### 1.3 一个规定行为例子

起床和早餐是 m1–m4；上班发生的 XX 事是 m5–m8。主模型只 hold 了 XX 事，宿主确认成功并记录当次输入书签 m8。之后聊到 m15，临换窗只提醒关注 m9–m15。早餐不自动补桶，原文仍在。主模型主动想起更早内容，可以按现有权限补记，系统不强迫。

## 2. 身份、数据与运行层

### 2.1 真实身份装载

第一条 OR 生成之前，宿主读取批准的身份/运行材料、当前有效 I 和 Mariposa 启动资料。不能发起一个空白助手回合再问自己是谁。不能用写死的名字替代批准身份，也不能绕过现有身份校验。

SDK 的安装、SDK 专属参数、订阅认证和 SDK 探针不是 OR 启动的前置条件。OR 使用独立凭据与能力校验；共有的身份、主体权限、资料版本校验仍然必需。当前驱动为 OR 时不得为了准备 SDK 而启动 Claude Code、读取订阅凭据或进行其握手。反向亦然。

### 2.2 三类持久数据

- **聊天原文**：message_id、房间、真实角色、实际时间、修订号、发布/中断状态、正文和稳定附件引用。编辑形成修订，不无痕重写来源。
- **模型协议轨迹**：每次实际送出的有序输入投影、主模型正式输出块、工具调用/结果、宿主事件及必要协议字段。用于续请求、恢复、复现布局；不是另一套语义记忆。受不低于原文的访问保护。
- **运行元数据**：窗口、请求用途、输入 manifest、hold 收据、书签、提醒结果、缓存/费用。普通诊断日志只放 ID、版本、计数、状态及 keyed HMAC，不写私密正文或 key。

SDK 的 UI 思考投影继续与模型上下文分离；不能由页面思考文字逆向构造原文或协议字段。协议轨迹与可读思考不是同一数据源，详见第 10 节。

### 2.3 最小概念模型

复用现有表；只有确实缺失才新增字段/小表。下面是逻辑契约，不是宣称本机已有这些字段。

| 对象 | 必要信息 |
|---|---|
| ContextEpoch | id、room、driver/profile、模型/I/规则/工具版本、启动来源 manifest、状态、active_revision |
| ProviderRequest | 本地 request_id、attempt、epoch、用途、来源 manifest、发送开始时间、OR generation_id、终止状态 |
| HoldReceiptLink | 领域真实操作/资源凭证、发起 request_id、发起时已见消息书签、来源绑定状态 |
| RotationReview | review_id、epoch revision、精确范围及消息修订、状态、完成决定、成功 hold 引用 |
| RawOutbox | 稳定源消息/修订键、授权范围、重试、正式来源确认 |
| RunRecord | room-scoped 序列、事件类型、脱敏 payload；支持有界分页和 SSE 回放 |

不要把窗口 ID 当 Mariposa Recall Session，也不要把 OR session_id 当服务器替你保存的聊天。

## 3. 主模型 hold 书签与一次提醒

### 3.1 成功书签

只有当前房间、当前窗口主模型实际发起的 hold 得到正式成功收据，才记录书签。书签位置取**发起该工具调用的模型请求实际看见的聊天输入位置**。不是桶的事件日期、绑定原文最大 ID、回执到达时的房间最新消息，也不是后台导入/外部 Chat 客户端的写入时间。

记忆已创建与原文已绑定分开显示。创建成功但绑定待恢复时，可以显示创建事实；不能伪称绑定成功。已经承诺执行而结果不确定的来源绑定仍属于真实待恢复副作用，不能通过零 hold 决定抹掉。

同一收据重复到达不产生新书签。旧窗口迟到收据只能补原请求记录，不能推进新窗口。主模型只说“记住了”、调用尚未执行、网络结果不明，均不能成为成功书签。

书签是“以后默认从哪里提醒”的位置，**不证明此前所有内容已经逐条考虑或成桶**。

### 3.2 精确提醒范围

在安全回合边界固定本窗原话 manifest 与修订：

1. 有本窗成功书签：默认范围为书签之后、截至本次已携带高水位的真实对话。
2. 没有书签：范围为本窗实际携带的真实对话，不扩大到全库。
3. 扣除已经完成同消息版本提醒的范围；失效修订不能套用旧回执。
4. 新窗口携带的旧尾段，可以继承其有效“已提醒”凭证或“在成功书签之前”的焦点起点依据。后者只叫焦点豁免，不标成 reviewed/held，避免每次轮动又强制检查早餐。
5. 范围为空：记录 `skipped_empty`，不收费叫模型。持久记录范围定位依据，不能单靠 max(sequence) 伪造不连续来源的覆盖。

主模型已经正式生成的可见回复可在随后的提醒输入中按原文携带；书签本身仍取生成 hold 调用时的输入视野。尚未送给模型的新用户消息不进入旧窗提醒范围。工具/RAG/时间/控制事件不是双方原话，但主模型可以按已授权工具证据记实际发生的事，不伪造为用户发言。

### 3.3 主模型可以直接放行

固定完成能力：`context_review_complete`，参数只需宿主签发的 review_id 及 `no_new_hold` / `holds_completed`。主模型不需要写理由、摘要或重要性分。

宿主验证：当前 room/epoch/revision、活动 review、完成范围、发起资格及真实副作用账本。工具 schema 从开窗就固定在可用列表内，不能临提醒才更改工具集合或强制 tool_choice。

- `no_new_hold`：本次没有新增正式 hold，且没有未解决的已发起写操作，允许换窗。
- `holds_completed`：本次确有已核实的成功 hold，未解决副作用为零，允许换窗。
- 同一批 tool_calls 里既有 hold 又有 complete：先执行并核实写操作，最后验证 complete；不得并发抢先放行。
- known-failed 的写操作可由主模型明确放弃后按现有错误合同解除；unknown 结果先核实，不得直接当没写。
- 空结果、拒绝、截断、非法参数、网络失败不等于 `no_new_hold`。允许有界恢复，不循环催促无限收费。

完成是“本次可以换输入窗口”，不代表计划已完成或语义事件已 CLOSED。每个正常回合无需调用该工具。

## 4. 自动换窗与容量预算

### 4.1 工程初值

| 条件 | 动作 |
|---|---|
| 连续聊天 | 同一 epoch 向后追加，不每轮提醒 |
| 容量预警推送/弹窗 | **2026-10-08 退役**：不新增预警弹窗或提醒模型，也不保留 56k 预警展示；token 占用显示、64k 软线计算与 §4.2 硬门照常 |
| 64,000 当前输入 token 软线，或下一输入将达到该线 | 完整回合边界提出换窗，先做必要的一次提醒 |
| 距上一条真实用户消息至少 6 小时 | **2026-10-08 晚间裁定：不触发换窗**——静默只是睡觉，醒来继续原窗（缓存冷则如实计费）；换窗唯一自动基线=64k 软线；无夜间定时模型调用 |
| 身份/权限/必要工具合同或显式模式改变 | 按有效性要求换窗，安全撤权立即生效 |
| 零点、1h TTL 到期、普通 hold 成功 | 不单独触发换窗或语义闭合 |

~~6h 比较使用本条入站消息之前的 last_real_user_at~~（6h 触发已随 2026-10-08 晚间裁定删除：静默不换窗）。服务器接收/业务时间及消息事件时间分开；系统重启、面板刷新、保温、提醒及主动消息不冒充用户活跃。绝对时间持久化 UTC，业务日按 Asia/Shanghai。

64k 是一次输入的工作集软线，**不是所有请求累计计费 token**，也不是模型最大上下文，也不是供应商硬上限。cache-read token 仍占当前输入。64k 软线与 T/R/S 容量预留仍是配置初值；56k 预警与 12k 自动携带初值已随 2026-10-08 修订退役。新窗总量不再有"约 32k"固定目标——由人工选集（§5.5）实际大小与请求级容量终检共同决定。

### 4.2 每次请求的硬门

```text
实际待发全部输入 I
+ 配置的最大输出 O（含模型协议中占额度的推理输出）
+ 有界后续工具输入预留 T
+ 换窗提醒及其必要 hold 往返预留 R
+ 安全余量 S
<= 实际所选模型/端点容量 C
```

初值 T=8k、R=8k、S=4k；最大输出继承用户已批准模型配置，没有已配置值时安装模板先用 8192，前台明确可调。有效软线 `min(64000, C-O-T-R-S)`，预警不高于软线减 8k。输入估计必须带来源/精度，未知容量不得画假的百分比。

所有连续工具回合每次重算，预留不是无限消费额度。可能需要多次 hold 时有界累计增长，必要时提前进入提醒。不得偷偷降低已批准的推理档位、吞掉尾部或者以文字截断替代源码门控。新启动必需身份超额时说明缺口，不能反复新建窗形成循环。

大用户输入到来先保存；若会越软线，先对旧窗已见内容完成提醒，新输入只进新窗一次。大附件/工具结果在首次进入轨迹之前做有来源的分页/范围读取，保留完整证据，不事后把已经发送的旧结果改成摘要。

### 4.3 正常状态机

```text
ACTIVE → ROTATION_REQUESTED → WAIT_SAFE_TURN
  → REVIEW_PENDING（或 skipped_empty / 已有有效回执）
  → REVIEW_COMPLETED
  → PREPARING_NEW（读取身份、资料、近期原话；旧指针仍保留）
  → READY_NEW → CAS_SWITCH → ACTIVE_NEW / CLOSED_OLD
```

同房间只一个生成/检查执行者。真实工具回合和待决路由票据未处理完不能切换。用 compare-and-swap 校验旧 epoch/revision；跨服务不宣称单个数据库事务能保证全局原子性。

提醒完成但新窗准备失败，保存同范围有效回执，恢复不再次付费检查。提醒期间到来的消息先排队，不纳入已经检查的范围。容量已近硬界而提醒未完成：保存新消息，显示待恢复，不静默丢掉旧输入。

### 4.4 静默恢复与故障例外

2026-10-08 晚间裁定：长间隔恢复**继续原窗，不提醒、不换窗**（换窗唯一自动基线=64k 软线）。主路径从持久协议轨迹重放旧窗上下文；旧缓存冷掉则如实计费，不宣传“隔夜免费”。不在静默期间周期唤醒，也不重查全库。换窗检查只在 64k 软线（或身份变化受控换窗）时发生。

轨迹不可恢复或已撤权时，不能假称已完成检查。报告具体状态，走有界、明确来源的恢复或用户明确放弃本次检查；恢复不建立全量补记任务。被撤销的内容不得为了检查重新外发。安全性优先于提醒和缓存。

## 5. 新窗启动：不生成另一份摘要，不自动携带历史

宿主在首次模型请求前装配四样东西：批准身份/规则和当前 I；现有 Mariposa 开窗资料（换新窗必拉最新）；**她确认的历史原文选集（§5.5，可为空）**；本次待回答输入与新消息。自动挑选近期历史（12k 预算、固定条数、摘要替代、DS 代写）自 2026-10-08 起一律不存在。

1. **I**：当前批准版本只装载一次，长内容使用领域分页读取至完整必需身份，不把第一页 2000 字当完整身份。并发分页遇 snapshot stale 重取，不拼接不同版本。
2. **Mariposa bootstrap**：复用已获授权 entry/profile 的正式响应投影，包括近三个自然日条目、相关未完成计划、临近纪念及当前合同允许的重要资料。不要把所有 WIDE 桶全文常驻。存在“未变”薄响应时只能复用自己确实保存的同版本快照；不能给一个没有内容的新窗只传 snapshot_id。
3. **字段权限**：bootstrap 与普通召回是不同出站合同，不能凭字段名推导它们权限相同。现有已读 bootstrap 的三日条目包含标题、分类、心情标签和心情文字；宿主应消费该获授权视图，不额外调用详情接口扩展回忆/keep 理由，也不以适配为名修改 Mariposa 出站规则。GLM 核对实际部署合同与代码一致性；发现未经批准字段只报告并隔离该字段，不自行全局改业务。
4. **未完成事件**：仅使用真实已有状态、桶和来源引用。普通闲聊不强制建 OPEN/QUIESCENT/CLOSED；缺少专门事件实体不能在启动时找小模型编一份“未完故事”。真正 plan 状态沿既有领域契约，不因换窗自动完成。
5. **历史原文（人工选集，§5.5）**：历史进入新窗的唯一途径是她确认的选集。选集只是对既有消息的引用（message_id、修订、内容 hash），装配时服务端按真实修订读取正文、按消息 sequence 恢复顺序；不相邻段落如实标注间隙，不假装相邻。没有 12k 预算挑选，没有固定 30 条，没有摘要替代，也不要求完整问答组成对。
6. **读取无副作用**：bootstrap、状态和记录面板读取不自动调用 hold/open→confirm，不更新“明确打开”时间。新增 hold 只由主模型实际工具动作产生。
7. **新消息**：排队消息从历史选择中排除，到尾部只注入一次。多条连续用户输入按现有顺序和合并政策，不以 API 转换随意改写说话人。

原文、桶、plan 和 I 的长期保存不依赖缓存。缺少关键身份时不能产生默认助手；非关键来源缺失须显示部分可用，不能称记忆全恢复。

### 5.5 人工选集换窗（2026-10-08 修订核心）

1. **三种清单严格分离**：`selection_manifest`（她准备给新窗什么）、`seen_manifest`（当前窗口实际发给模型什么）、`hold_checkpoint`（最近成功 hold 时的已见水位）。选择确认不等于已发送，已发送不等于已 hold，书签之前不等于全部入桶；不得根据书签反推"未归档原文"或删除原文。
2. **未提交 ≠ 空选**：她没操作、退出面板、超时、网络中断，都不是"选择为空"。明确空选必须显式确认（`explicit_empty=true`，items 为 `[]`）；awaiting（items=null）与 confirmed-empty 不等价。
3. **选择只建立引用**：不重复发送消息、不产生新 messages/revisions/outbox/ingest、不创建聊天气泡或归档任务。原文仍在原聊天位置；前端提交的正文不进入模型，服务端从真实修订读取。引用旧消息不触发明开、续期、hold 或新归档。
4. **选择面**：允许从当前获授权房间全部可浏览历史选择——不限最近 N 条、不要求连续、不要求完整问答组、不受 hold 书签限制。当前待回答与排队输入不得被重复作为历史带入。
5. **容量**：选集 token 估计连同 A/B、工具定义、待回答输入、输出/工具/检查余量一起计算；超限返回 `CONTEXT_SELECTION_TOO_LARGE` 与缺口估计，保留草稿、不裁原文、不叫 DS 代写。预计装下仍做请求级容量终检。
6. **冲突**：选取期间所选消息被编辑 → `CONTEXT_SELECTION_STALE` 并定位冲突引用；不静默换新正文、不拿相似内容冒充。
7. **入口统一**：手动、64k 预测越线、6h 静默、身份/配置变化、重启恢复、首次懒初始化都适用同一选择规则。需要换窗而无有效确认选集：持久 awaiting，用户输入照常保存，房间状态加 `CONTEXT_SELECTION_REQUIRED`，暂停该房间模型派发并**释放串行锁**（等待选择不得占住房间执行锁，否则确认请求自己进不来）。仅真正全新的空房间首窗可自动记录空初始化；已有历史但无活动窗不得擅自空选。
8. **确认与恢复**：确认后进入同一串行队列 → 校验选择 → 旧窗既有 hold 提醒/unknown 恢复 → 取新鲜 bootstrap → 整体容量检查 → prepare 新窗 → 同事务提交 selection consumed、初始轨迹/manifest 与窗口指针 → **以原 input_message_id 恢复待回答输入，只发一次**，不再调用一次"发送用户消息"。旧窗提醒成功而准备失败：保留回执，重试不再次付费提醒；任何失败保留原文，新窗未完整就绪不关旧窗；双击/重复请求/两端并发只能产生一个新活动窗。网络/模型调用不放进 SQLite 写事务。
9. **旧窗 hold 不受选集影响**：即使新窗选集为空，旧窗里真实已见未检查内容仍按 §3 发提醒；只有旧窗确实无已见内容才可 `skipped_empty`。无轨迹评审回退按真实轨迹/派发证明重建范围，与新窗选集分离。

### 5.6 DS 日结与自动携带退役（2026-10-08）

DS 昨日日摘要的完整运行链（摘要服务、注入接线、专用配置、千问预留分支、派生摘要表）与各新窗入口的自动近期历史回退整链退役：不再生成、不再注入、不再自动回退。DeepSeek **主聊天驱动**、hold 提醒、成功书签、原文、消息修订与缓存轨迹全部保留。旧配置键经一次性配置迁移或结构化退役说明处理，不静默忽略。历史窗口中已发的摘要/12k 段是过去真实输入证据，不改写；升级后旧活动窗按 legacy 处理，经一次受控人工换窗进入新政策。

## 6. OpenRouter 专用驱动

### 6.1 配置和认证

使用 `https://openrouter.ai/api/v1/chat/completions`。API key 只由后端受保护的凭据引用或 `OPENROUTER_API_KEY` 读取，不放前端 localStorage、HTML、URL、Git、测试夹具、错误回显或完整请求日志。现有应用认证、CSRF/Origin/房间 ACL 保留。

模型使用当前用户已选的**明确 OR model ID**；不要将 SDK 的短别名直接发给 OR，不用 `auto`、`latest` 或 models fallback 数组。配置模板未设置型号时显示“模型未配置”，优先从现有批准配置/设置迁移，不能由 GLM猜一个替代。设置页提供 OR/SDK 模式、明确型号、凭据已配置状态、已批准的输出/推理参数；切换模式属于有权限的配置写入，安全创建新窗而非悄悄切换。

OR 配置与 SDK 的 `settingSources`、SDK `systemPrompt` 装配、resume ID、订阅认证分开。共享中间输入段/业务授权，不共享供应商会话和 KV。不要把 OR 请求套进 Claude Code 再声称完全掌握了 API payload。

### 6.2 请求控制

以下是**控制片段**，完整示例见 `fixtures/or-request.example.json`：

```json
{
  "model": "<已批准的明确 OR 型号>",
  "session_id": "<本房间与模型配置的持久匿名标识>",
  "stream": true,
  "provider": {
    "only": ["anthropic"],
    "allow_fallbacks": false,
    "require_parameters": true
  },
  "cache_control": {"type": "ephemeral", "ttl": "1h"},
  "plugins": [{"id": "context-compression", "enabled": false}]
}
```

`anthropic` 是 OR 内部上游选择，不是官方直连。启动前用 OR 当前 model/endpoint 元数据核对可用性、tools/媒体/参数与容量；这不需要提交私人正文给另一个服务。[R01,R03,R05]

session_id 最长按当前官方 256 字符校验，同窗普通聊天/提醒/MCP 续请求使用同一值；模式或模型配置变更单独命名空间。不要每次随机；避免真实姓名。**它只用于路由/日志关联，不储存历史，也不保证缓存命中。** 不设 provider.order，避免覆盖 OR 的自动黏性；only 限定上游集合仍不等于锁住某个物理缓存节点。[R01]

所有实际路由设置和继承 preset 都要检查：不允许隐藏 model fallback、压缩、记忆摘要、未批准工具/连接器或不同计费模式。请求不设置不必要 preset/transforms，不引入 response healing 为非法工具参数补 JSON。发现账号/预设启用了会返回旧答案的 response cache，禁用或给出设置阻塞，不能混称 Prompt Cache 命中。

不伪造“所有1h参数必然透传”的探针结果。参数/端点不支持就报配置错误，不静默换上游、SDK、型号或5m。`require_parameters` 只筛兼容端点，不替代真实缓存测试。[R03]

### 6.3 中间驱动契约

新增 provider-neutral 请求信封，按 driver 区分：SDK 有已装配 options/resume；OR 有不可变 messages/tools/profile 和 streaming transport。不要把所有 messages 压成 SDK 的一条 prompt，也不要让 OR 样式 usage 伪装成 SDK usage。

保留 AbortController、request/attempt/turn ID、状态事件、发布顺序/fence 和错误分类。OR 每个模型调用具有独立 generation ID；一个用户 turn 的多轮工具调用会有多个模型请求。

插件及模型元数据不能擅自升级配置。已批准 privacy/data collection/地域策略不得为提高命中降低；后台保存自己的原文不代表 OR 或上游没有各自数据政策，1h不是“保证不落盘/零保留”的声明。

## 7. 一小时缓存精确实现

### 7.1 布局及字节/块稳定

```text
固定 tools + 批准系统规则 + 本窗口 I               → 显式缓存点 A（1h）
Mariposa 本窗口启动资料快照（作为资料、非高权指令） → 显式缓存点 B（1h）
人工选集历史 + 后续完整协议轨迹 + 本轮新增内容      → 顶层自动尾缓存（1h）
可选上一次已发送且仍完全相同的可缓存边界           → 保护点 G（1h）
```

缓存点覆盖从开头累计至该处的整个前缀，不是四个互不影响的小盒子。所有点均明确 1h。A 不足最小缓存长度时 B/尾点可达到；不填无意义字数。原生顺序包括 tools、system、messages，OR 最终转换不可全见，记录自有边界和真实 usage，不声称已审计不可见上游。[R02]

A 的运行规则与 I 首次装配后固定。B 只冻结这一窗的输入快照；新 hold 在 Mariposa **立即正式生效**，其收据/新信息通过尾部工具结果进入当前轨迹，不每次重建 A/B。

**注入缓存模型（她裁定 2026-10-07，复审③收窄）**：开窗注入；同窗修改靠对话上下文承载、注入不动；掉缓存=重发冻结副本（非重拉）；**换新窗必拉取最新开窗包**。经网页/API 在同窗中途改的桶/I，注入到下一个新窗才带上——按裁定接受（改 i 的对话在轨迹里，模型读得到）。原"权限撤销例外"按同日裁定收窄归档：撤单条记忆授权的场景被裁定为不会发生，不再作为驱动信号；关键身份/事实更正经由"换窗必拉最新+对话轨迹承载"覆盖。工具面的运行权限撤销（:285）不受本条影响，仍每次检查。

历史时间、召回片段、工具参数/结果、附件引用第一次规范化后固定。下一轮再追加新时间，不修改上一轮“现在”。工具名字/描述/schema/顺序在 epoch 内固定。不要每轮 list_tools 重排，也不要为了提醒缩减 tools 或改 tool_choice。

附件不能每轮生成不同的短期签名URL来表示同一张图片。保存稳定资产ID、内容版本和获授权的实际输入表示；URL过期时按同一版本重新解析并明确记录前缀变化，必要时换窗，不使用已失效链接冒充相同输入。模型/端点不支持原生音频或文件时走已有Siren/oído等已授权能力，不把原文件盲送未知路径；媒体token单独纳入预算。

前台“hold 书签”是装饰性元数据，不插入旧消息正文。提醒限定关注范围，但不删除之前的历史前缀；已经在输入里的原文不重复粘贴一次。

### 7.2 自动与显式断点

顶层 `cache_control` 自动向末尾可缓存块推进。通常 A、B 两个显式点加一个自动点；必要时 G 占最后一个槽。显式最多3个，自动占1个，总计不超过4。重复位置去重。历史轨迹不永久累积 cache_control 标记，发送副本统一重规划。[R01,R02]

上游只在设定断点处建立候选条目，并有约20个内容位置的回溯窗口；突然增加许多块会越过上次断点。因此保存已发送边界的定位与前缀指纹，仍在当前轨迹且可合法标记时增加 G。先选实际观测发生读写的请求边界；usage 只有总量，**不能据此声称某个具体边界必然存在**。该位置只能标为已发送/候选保护点。[R02]

原生工具块有特殊位置计算，不能拿 UI 气泡数当原生 block 数；OR 的内部重分块未知时保守标记 G 并实测。不可合法标记该处则记录保护未覆盖，不通过写一个未知 JSON 字段碰运气。A/B 仍可复用，部分 miss 不允许改变记忆正确性。

固定边界和工具清单指纹可以本地验证；上游实际命中看 P3。顶层自动遇末尾已有同TTL显式点可能复用该点，不能因此当成第五个点。代码主动限额，不依赖400发现错误。

### 7.3 TTL 和路由两个时钟

缓存有效期按上游处理规则，从请求**开始**计时，不能从流式输出结束才加一小时。仅凭本地时间计算是估计，不是可查询的缓存对象。OR 路由黏性另有约10分钟闲置过期，不能认为 session_id 使路由保证一小时不变。[R01,R02]

读取到缓存可以续期；重复计数请求不是缓存保温。缓存过期后仍可重发相同轨迹，重新付相应费用，不需要删历史或重新造桶。跨 epoch 只要 A 与实际上游匹配仍可能复用 A，B/历史改变通常重新写；不可承诺跨窗全命中。

### 7.4 参数与计价不能套错型号

缓存最小长度、读取折扣、模型容量、推理档位按选定型号/端点读取并保存带日期的能力快照。不要将某个旧型号的4096门槛或0.1倍读取价格当成所有Claude的常数。价格用于展示估计，不取代 OR 实际 cost。[R01,R02,R10]

1h 是正常聊天的显式参数，不等于一定整夜保温。主模型提醒仍重新携带所需历史，命中按读缓存计价；不再交另一个模型分析不等于只计费提醒那一句话。

## 8. 递话、MCP 与来源安全

### 8.1 宿主控制事件

开窗时固定系统规则声明：宿主可发送换窗检查事件，工具授权由服务端验证。动态提醒在旧轨迹**尾部**添加，内容使用 `prompts/pre-rotate-review.txt`，只含本次原因、范围 ID 与固定指令。

“系统递话”是业务来源，不意味着可以把任意 `role:system` 放在末尾。OR 适配可能将其合并到前缀。默认采用明确 provenance 的 synthetic user 内容块，宿主记录真实 origin，且不进入聊天原文；它不是高权限授权机制。用户模仿模板不会创建 active review，不会得到签发回执资格。安全/身份规则仍在固定 system，不能降为检索资料。

若采用原生中途system，必须同时证明选定模型和 OR 路径支持且不重排；不把这项作为基础实现的必要依赖。宿主隐藏普通对话输出，但仍处理合法工具和用量。提醒用途为 `pre_rotate_review`，不能转成用户气泡、TTS、推送或免费keeper。

### 8.2 工具循环

```text
OR 请求 → assistant(tool_calls + 必须的协议字段)
→ 完整验证后由宿主 MCP 客户端执行
→ 原样保存 assistant 调用和同ID的 tool 结果
→ 续请求同样经过 P1/P2/P3 → 最终回复或下一次调用
```

OR 不会替本地 MCP 执行工具。[R04] 独立适配 MCP initialize/list_tools/call_tool、认证/超时、错误形状与资源引用。SDK 现有 MCP 配置不等于 OR 已经有执行器。工具名称做确定性无碰撞映射；JSON schema 不支持的关键约束不能偷偷删掉；无法兼容标记能力缺口。启动固定 allowlist，运行权限每次检查，即使 schema 为缓存保持不变也不能执行已撤销能力。

输入完整 JSON 组装/校验后才执行工具；流式参数中途绝不边收边写。`isError`、业务拒绝、网络unknown区分，原样形成有界工具结果。独立安全读可按已允许并发，写操作及 review complete 按依赖串行；不能为降低延迟越过主体或权限门。

工具输出先存受保护证据，再选择首次注入范围。大结果使用分页/ref，不由小模型总结。不是所有字段都可给主模型；仍使用服务端已授权投影，不绕过 Jev、source gate 或明开规则。

### 8.3 Mariposa 真实接口适配

本轮实际代码可见 `memory.hold` 与 `source.bind` 分离；hold 的 `raw_refs` 非空被显式拒绝。因此**禁止在 OR 的 hold 里臆造 raw_refs 一步绑定**。使用已验证正式 source 身份，再按既有绑定入口提交；多范围可多次绑定并记录每个收据。

已有 source.import 是导入文件型入口，不等于已经有在线消息追加/修订协议。原文 outbox 生产者存在，也不等于同步消费者已验收。WP0 必须定位正式可用通道；若缺在线追加和跨请求幂等回执，按 `contracts/mariposa-integration.json` 提交最小服务契约，并在相应仓库授权范围内补足。不要直接连接 Mariposa SQLite，也不要把普通聊天伪造为 Claude 导出文件长期冒充 live 协议。

已有领域 hold 未必支持网络层 operation_id 去重：本地保存执行意图只能防同进程重复，不能解决“远端已写成功、响应丢失”。必须找到实际远端幂等/操作状态出口；缺失时该情形标 unknown并阻止盲重放，最终跨服务验收不得通过。新增领域契约只围绕同一 hold/source 能力，不增加第二套记忆或改召回事务模型。

来源晚到允许按现有明确支持的 pending-binding 规则处理；不能把兼容形参 raw_pending 的存在当作完整工作流已实现。补写日期、现场/回顾模式、心情写门、分类和 plan 绑定规则由领域服务决定，不为过测试默认补“日常”。

### 8.4 判断总开关的消费（2026-10-08 修订）

召回判断的正本开关只在 Mariposa（持久政策记录，仅人类网页可写）。estómago 的合同是**纯消费**：

1. `memory_recall_next`（宿主工具）：只消费 Mariposa 已冻结的结果集（session/scope/result_set/cursor 与模式信息），不修改查询、不先 start/refine。翻页不重新检索、不重新判断、不增加召回轮次 COUNT。
2. `refine` 保持独立动作（明确修改查询）；分页游标与 refine 引用、Raw 续搜引用分槽，不互换。
3. 出站模式字段（`judge_mode`、`judge_policy_revision`、`judgement_status`、`pagination`、`retrieval_coverage`）必须穿透到主模型可见的工具结果，不允许宿主 slice/丢字段。
4. 政策中途切换：旧 revision 的续页返回 `RECALL_POLICY_CHANGED`，如实上抛，不自动另起收费查询、不悄悄混模式。
5. 关闭模式（judge off）下周家明拿到的候选全集仍按页交付；宿主不替他一次读完所有页，也不把未读页标成已审阅。

### 8.5 原文回读 `conversation_read`（2026-10-08 新增）

主模型只读工具，围绕已知消息回读原文；已知引用的展开不经判断器（仍做来源/权限/版本验证），模糊查找继续走 recall。

1. **范围**：room 从 ToolExecContext 派生，模型不能自填房间；可读同一获授权房间的其他已保存历史——已选消息只是定位锚点，不是读取权限全集。跨房间拒。
2. **内容**：默认只返回真实 owner 消息与已正式发布的 assistant 消息（ID、revision、sequence、speaker、occurred_at、正文、content_hash）；排除 system/tool/ReasoningProjection/未发布草稿。不提供 include_cot 参数，UI 思考不进任何回读面。
3. **分片**：每次读取有条数与完整 JSON 字节上限；长单消息按码点边界显式分片（start/end_char、content_complete、cursor 续页），拼回逐字一致；首条过长不得形成空页活锁。指定版本读不到时如实返回，不用相似正文或当前修订冒充。
4. **同步状态**：源同步未完成可返回本地原话并注明 sync_state，不伪造 Mariposa source 身份（QUOTE_NOT_SYNCED 边界沿用）。
5. **已见接线**：只有实际进入下一模型请求的片段才加入该次 seen_manifest/seenMessages（必要时在既有 manifest 扩展字符范围，不建第二套覆盖系统）；仅调用工具或前端预览不算已见。回读不推进 hold 书签、不延长衰减、不制造聊天气泡、不触发明开续期。

## 9. OR 流式返回、重试和费用

### 9.1 返回处理

识别非2xx JSON错误、200内的SSE error、注释心跳、UTF-8跨网络块、多行data与DONE。解析失败是协议错误，不忽略关键片段继续宣称成功。[R06]

OR最终usage帧可能重复 finish_reason，并非只有 choices=[]；它是记账帧，不是第二次结束/第二份工具执行。先按请求完成一次业务状态，再补完整usage；支持返回头 X-Generation-Id 与正文 ID 关联，不同ID冲突要报告。[R06]

工具参数未完整、结束原因为 length/error/content_filter、缺少可靠终态，不能发布完整成功或完成review。正常显示已经正式发表的部分文字需标明中断；不捏造未生成后半段。保存/交付失败只恢复保存和送达，不能重新调用模型产生另一套承诺。

### 9.2 重试和取消

401/402/配置400不自动重试；429/短暂网络故障在无已发布输出/已发起副作用且已有授权重试预算内有界重试并遵守 Retry-After。不因为异常改模型/上游/SDK。已向上游发送但结果未知仍可能收费，记录attempt，不声称请求幂等可免重复计费。

建议最多两次恢复尝试，不包括用户明确手工重试；超时按现有配置和模型能力设置，不用过短read超时误杀长推理。浏览器断连与用户按停止区分。停止时abort上游+本地generation fence，迟到文字/工具不继续执行；迟到usage仍记录真实消耗。

### 9.3 统一账本

保存 raw usage 和规范字段，不混用两种口径：

```text
OR input_total = usage.prompt_tokens
OR cache_read  = usage.prompt_tokens_details.cached_tokens
OR cache_write = usage.prompt_tokens_details.cache_write_tokens
OR noncached   = input_total - cache_read - cache_write（全字段已知且相容才推导）

原生 Anthropic 总输入 = input_tokens + cache_read_input_tokens + cache_creation_input_tokens
（仅当该 SDK/接口确实采用此字段口径；不得无条件套所有 SDK 事件）
```

OR的详情是总prompt内分类，不能再加一次。完整度不足、字段缺失或冲突标unknown/anomaly，不能将负值clamp成零隐藏问题。输出/推理明细同理避免重复相加。[R05]

一条真实模型请求只计一次；流式与查账两份观测不是两次消耗。`usage.cost` 为已报告总额；不能再加 `cost_details.upstream_inference_cost`。价格估计与账单金额分栏。请求失败/取消但费用已知仍应显示已花；整turn有未知项时显示“已知小计 + 存在未知”，不丢掉已知钱也不写零。

日累计费用、当前输入占用、每轮费用、检查费用各自显示。数据缺失可对已知 generation_id 做一次受控查账，不重新生成文本，也不频繁轮询全部历史。[R05]

## 10. 思考隔离与 SDK 兼容

UI可读思考、模型协议继续态、原话/记忆是三种对象。`ReasoningProjection` 不得转进 model context、bootstrap、hold、TTS、推送和近期原话。

OR某些模型在工具续请求中需要保留完整 `reasoning_details`（含签名/加密等结构），不得重新排列、截断、重签名或从UI摘要补造。[R07] 同一模型协议继续态应作为受保护opaque字段处理，不成为可检索记忆或跨窗交接资料。

**严格“不回灌任何思考”的已有合同如同时禁止上述协议字段，不能由 GLM 自行宣布豁免。** 先核对已批准权限与实际型号：能在合法模式下完成工具循环就保留该模式；必须传字段而合同不允许则标 `REASONING_PROTOCOL_BLOCKED`，提供确切冲突证据，不靠删字段试错、改模型、禁用推理或开放全权限来掩盖。一般的UI隔离不能冒称供应商内部绝无推理续态。

推理显示开关不是推理计算开关。有些型号推理为mandatory，`exclude`只是控制返回；模型元数据和实际请求决定可配项，不把所有SDK effort字符串照搬OR。[R07,R10]

SDK保留现有公开接口、认证/VPN安全约束和版本锁。正常容量探针在宿主提前做；按已装SDK版本核对 PreCompact / PostCompact 能力，不能把官网支持写成本机已通过。PreCompact仅兜底，不是等到超限才塞hold提醒；某些补救场景阻止compact仍会使请求失败。[R08]

OR显式关闭上下文压缩插件，不启用供应商compaction。SDK若仍产生compact，事件明确记录，摘要不导入原文/桶/新窗；按真实原文和已完成书签恢复，不把它当review通过。[R09]

## 11. 三处探针与前台记录

### 11.1 探针位置

```text
输入/工具结果先保存验证
→ 构建候选输入
→ P1 容量/闲置/回合/书签预检（系统递话前）
→ 有必要时尾部追加一次提醒
→ OR序列化与缓存规划
→ P2 最终发送校验（含提醒/tools/媒体/预算/权限/route）
→ OR响应与MCP循环
→ P3 实际usage/finish/收据/前缀观测回填
→ 安全准备并切换窗口
```

每次MCP续请求同样经过P1/P2。P1用程序，不读语义；P2不能被“有API key/HTTP200”替代。计数默认本地估计+真实usage校准，媒体/工具/模型变更扩大误差范围；不以固定字符比例冒充精确token。未验证可用的官方计数接口不可变成新增私人内容外发路径。

缓存探针是正常请求的观测，不是在每轮前额外收费问一次“热不热”。count_tokens不负责建立缓存，不能冒充保温。估计与actual清楚区分。

### 11.2 必做“记录”按钮

复用 `apps/web/src` 当前页面：聊天顶部“记录”；桌面侧栏，窄屏底部面板。保留原画风，不引入前端框架迁移；Enter换行、独立发送键、IME和多行保真全回归。

显示：当前模式/明确模型/窗口；当前输入估计及精度、上次actual、有效软线（预警推送已退役，§4.1）；hold创建成功和绑定状态、来源定位书签；提醒范围/发送/零新增或N条/失败；换窗结果及原因（含 awaiting 选择与 CONTEXT_SELECTION_REQUIRED 状态）；人工选集计数与状态；原文本地已存/待同步/已同步；配置1h、上次真实缓存读写和费用、估计热时限；保温关闭。

“未新增hold”正常显示，不用红色漏记警告、不显示绑定率/记忆覆盖率。“约58k/换窗64k”不是模型硬最大值；用量unknown不能画100%命中。“配置1h”“观测到缓存读取”“已验证延时复用”分开，不用一个绿灯合并。

打开/刷新面板、分页、SSE重连仅查询，不调模型、不触发hold/明开/换窗/保温、不刷新用户活跃。记录面板只默认显示获授权的ID/标题/状态，不曝完整prompt、签名思考、密钥、工具认证参数或跨房间资料。点击“定位原话”只定位；点击“明确打开桶”另走领域正式动作并保留回温语义。

建议复用现有events/service、HTTP鉴权及SSE游标。新增只读 room记录快照/有界事件分页，具体命名在契约附件中；SSE慢客户端有界缓冲，重连不重复追加UI事件。

## 12. 保温与主动唤醒

本任务不运行keeper，不新增常驻服务。1h参数始终随正常请求使用。三种用途保留区分：`chat`、`pre_rotate_review`、`proactive_turn`；`cache_keepalive`保留枚举但默认禁用。

后续开启keeper须用户控制和有限费用/时间授权，模型可在正常回合申请，不增加周期模型决定。复用确实发送成功的前缀，不重取时间/记忆，不执行工具，不发聊天、不写hold、不延长真实用户活跃。缓存已冷不主动重建；miss成本真实记录。可以共用调度设施，但不能借“保温”强迫周家明主动发消息。

## 13. 完成定义

代码文件存在不等于业务接通，mock通过不等于真实缓存命中。交付必须分别报告：离线逻辑、真实本地HTTP/MCP契约、OR流/缓存/计费、SDK兼容、前台交互和部署状态。真实模型调用须明确预算与授权，所有测试隔离正式数据。

按 `ACCEPTANCE.json` 逐项给出证据。未执行标 `NOT_EXECUTED`，真实阻塞标 `BLOCKED`，不使用总测试数量覆盖失败。业务取舍不得变成执行者自由选择的分支：原文全存、主模型自选、一次提醒、允许零新增、一个前台线程、无摘要、一小时缓存固定、**历史进新窗只经人工选集、判断开关正本只在 Mariposa、关闭模式候选全集分页可取**。
